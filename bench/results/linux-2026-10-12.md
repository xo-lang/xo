# Linux fixes from the first EC2 full run (2026-10-12)

The first full suite run on EC2 (log bench/results/remote/7755ca1.log,
git ignored) failed five ways that pass on the Mac. Each was reproduced on
Linux, traced, fixed, and given a regression test; two more failures
surfaced once those were out of the way.

## Setup

- Host: EC2 c8g.8xlarge spot (32 vCPU Graviton4, 61 GiB), Amazon Linux
  2023, kernel 6.18 (`al2023-ami-2023.12.20260930.0-kernel-6.18-arm64`),
  Go 1.26.1, clang 15.0.7, gcc 11 as `cc`, /tmp on a tmpfs.
- Launched with `scripts/remote-full.sh --hold` (new), working tree
  copied with rsync, commands over ssh. One instance, terminated after.
- Docker on the Mac was not running, so no container run (the
  2026-10-09 Docker run, linux-2026-10-09.md, used Debian with clang 19
  and no tmpfs /tmp, which is why it missed these).

## Failures, causes, fixes

| Failure (7755ca1) | Cause | Fix | Regression test | Gotcha |
|---|---|---|---|---|
| internal/build TestRuntimeObject/arm64: binaries differ, same size | gcc assembles the arm64 backend's .s to /tmp/ccXXXXXX.o; GNU ld names the STT_FILE symbol after it (6 bytes apart) | `.file "prog.s"` on Linux (internal/arm64, selfhost/arm64) | TestRuntimeObject | linux-arm64-file-symbol |
| internal/gen TestGoldenNoMono: text file busy | the bin cache copies across file systems (tmpfs /tmp); a fork in another goroutine during the copy held the write descriptor | copyFile writes under syscall.ForkLock.RLock | TestCopyFileNoTextBusy (fails on the first copy without the lock) | linux-etxtbsy-copied-binary |
| internal/llvm TestGoldenThreads/conc_stress, clock_timers, TestGoldenTasks/conc_stress, TestRuntimeEventLoop: fault: out of memory | ThreadSanitizer leaves about 96 GiB of address space for the program; 64 MiB fiber stacks ran out after about 880 fibers (mmap ENOMEM) | 8 MiB task stacks under TSan on Linux | the four tests | linux-tsan-fiber-stacks |
| internal/llvm TestHTTPFuzz, TestH2Sanitizers/address: memcpy NULL | h2_head copied and sorted an empty header list with a NULL pointer; glibc declares nonnull | copy and sort only when there are fields | TestHTTPFuzz, TestH2Sanitizers | memcpy-null-zero-length |
| TestH2Sanitizers/thread: connection refused | not traced separately | passed after the two fixes above | TestH2Sanitizers | |
| (new) TestGoldenThreads/native_ed25519: TSan data race | Ed25519 constants behind a plain flag | pthread_once | TestGoldenThreads/native_ed25519 | ed25519-lazy-init-race |
| (new) TestGolden, TestGoldenTasks for env_program, map_remove_bytes, unix_kill (every platform) | want.txt held bare stdout | regenerated with -golden-update (header only) | the goldens | golden-want-without-header |
| (new) TestGoldenThreads/unix_kill: TSan "use of an invalid mutex" in pd_ready | epoll keeps a registration while a spawned child holds the file; close alone did not remove it, and the poller later used the freed xo_pd. TestH2Diff ("raw data over the window") failed in 7755ca1 and passed in
both later runs on this host; it was not investigated further.
