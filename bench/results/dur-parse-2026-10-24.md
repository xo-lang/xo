# Duration.parse: one branch a digit instead of four, 5% fewer instructions, 2026-10-24

`text.parse_duration` walks the digits of a duration's numbers one byte at
a time. Each digit cost four branches: two for `c < 0 || c > 9`, one for
the magnitude guard, and one for the range guard after the multiply. The
digit loop now takes one branch for the digit test and none for the
guards, and the whole function is 5% fewer instructions.

## The change

std/native/llrt/text.xo, the integer part of a duration's number:

- the digit test is `!(c >= 0 && c <= 9)` on the computed digit, which
  the native backends fold into one unsigned compare (`sub`, `cmp #9`,
  `b.hi`), where `c < 0 || c > 9` took two branches and computing the
  digit twice took a second `sub`;
- the per digit magnitude guard (`nv < -2^63/10`) is gone: eighteen
  digits cannot leave the range (10^18 < 2^63 / 10), and a run longer
  than eighteen is read again with the guard, after the loop;
- the second per digit guard (`t < MIN_INT + c`) is gone: with the
  magnitude guard the product is exact, and the one sum that leaves the
  range, the last digit of -2^63, wraps positive, so one test after the
  loop finds it.

The fraction part keeps its guard a digit (a fraction may be longer than
eighteen digits and Go's parse saturates) but takes the same single
range test.

## A/B, one revision, A = base, B = the change

`xo bench --ab`, 12 rounds, `bench/perf/text`, one xo binary building the
same source with each side's std. B/A below 1.0 is better.

| workload | A instructions | B instructions | B/A | A wall ms | B wall ms | B/A |
|---|---|---|---|---|---|---|
| dur_parse | 148,877,955 | 141,418,651 | 0.950 | 18.44 | 17.16 | 0.931 (interval 0.622 to 1.233) |

The checksum of the row is identical on both sides. The two earlier
steps, taken alone, were 0.998 (the digit test) and 0.963 (the guard
merge); the count that removes the per digit guard is the rest.

## What is left in the loop

Per digit, the loop is now about eleven instructions: the loop test, the
bounds check against the Bytes' length (`cmp`, `b.hs`), the byte load,
`sub`, `cmp #9`, `b.hi`, the multiply, the subtract, the index add, and
the back edge. The bounds check is the next candidate and cannot go
without a view-aware data address: `raw.data` is the object's own bytes
and does not add the offset a view keeps in its length word's high 32
bits (cabi.view_data does and is private to the runtime).

## Coverage

The `time` and `strconv` corpora on arm64 and llvm, `stdfuzz` area time
(the duration cases), the wasm goldens and the full fixed point.
