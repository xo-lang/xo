# Second model family: Codex (2026-10-09)

The agent benchmarks rerun with OpenAI Codex as the subject, through
`bench/harness` (path 2b: Codex ran the arm loops itself and recorded
`runs.jsonl`). Raw outputs and the scorer reports are in `runs/codex/`
(gitignored): `SUMMARY.md`, `solutions.md`, `planted.md`,
`claude-solutions.md`, `claude-planted.md`. Model tier and settings were not
recorded in the summary; add them here when known.

## Solutions

| Measure | Codex Xo | Claude Xo | Codex Go plain | Claude Go plain | Codex Go strict | Claude Go strict |
|---|---:|---:|---:|---:|---:|---:|
| First try pass rate | 3/10 | 9/10 | 10/10 | 8/10 | 8/10 | 2/10 |
| Runs in total | 20 | 11 | 10 | 12 | 12 | 18 |
| Green now (current toolchain) | 10/10 | 8/10 | 10/10 | 10/10 | 10/10 | 10/10 |
| Diagnostics on final code | 0 | 2 | 15 | 68 | 0 | 0 |
| Hidden checks, task 01 | 17/17 | 17/17 | 17/17 | 17/17 | 17/17 | 17/17 |

Caveats:
- Claude's Xo tasks 01 to 08 were written against the checker only (no
  test runner existed then); the harness runs check then test for every
  task, so the Codex Xo arm faced a stricter loop.
- Codex wrote Go densely (several statements per line), so line counts are
  not comparable and are omitted.
- Claude Xo 03 and 06 fail with today's toolchain (a known overflow found by
  contract fuzzing, and XO0410); they were green on the toolchain of their
  day.

Codex's 7 Xo first runs that failed all failed at `xo check`, and its own
notes name the cause: habits from other languages (Rust style `Hash + Eq`
constraints, comma separated match arms, `var` at call sites), plus an
omitted generic effect argument that stayed abstract.

## Planted safety bugs (X classes, 30 per set)

Prevented or caught = inexpressible + caught by `xo check` + caught by
`xo test --race` (Xo); caught by the plain loop or a new strict finding (Go).

| Arm | Codex | Claude |
|---|---:|---:|
| Xo, translated from the Go bugs | 27/30 | 29/30 |
| Xo, independent author | 22/30 (25 with new warnings) | 23/30 (25 with warnings) |
| Go strict (plain loop + analyzers) | 17/30 | 14/30 |
| Go plain | 12/30 | 9/30 |
| Logic bugs (N classes), Go | 17/20 | 17/20 |

At compile time only (inexpressible or `xo check`), the Codex sets reach
19/30 (translated) and 4/30 (independent), against Claude's 26/30 and 14/30.
More of Codex's catches come from tests, partly because its Xo bases differ
(several Go bugs had no analog in its Xo code) and partly because the scorer
does not subtract base test failures, so "caught by tests" overstates
somewhat.

## Conclusion

- The safety result holds for a second model family: with Codex as the
  author, Xo prevented or caught 22 to 27 of 30 planted safety bugs against
  17 for strict Go and 12 for plain Go, the same ordering as with Claude.
- The cost of an unfamiliar language shows up clearly: Codex needed 20 runs
  for Xo against 10 for Go, with 3/10 first try passes, all failures at the
  checker from other-language habits. Claude, which had the spec in context
  through many sessions, did not show this.

## Next experiments (ranked)

1. Habit diagnostics: give XO errors for the exact habits Codex hit a help
   line and a machine fix (`Hash + Eq` constraint syntax, commas between
   match arms, `var` at a call site, omitted effect argument left
   abstract), with golden diagnostic tests; then rerun only the Codex Xo
   arm and measure first try passes (target 7/10 or better).
2. Spec gaps Codex reported: `Clock.sleep` cancellation unwinds instead of
   returning a typed error a retry API can return; `read_line` on stdin
   cannot be stopped by a stop request; no `Json` for tuples; no
   `Duration.parse`.
3. Scorer: subtract base test failures for "caught by tests" so the Xo
   rates are not overstated.
4. Record the Codex model tier and settings, and run a second Codex pass to
   measure variance.
