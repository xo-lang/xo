# csv.parse against Go's encoding/csv, 2026-10-22

Native Xo (`--backend=arm64`) on main with views (decision 0330), before and
after this change, and a Go twin (go1.26.1 `csv.NewReader(...).ReadAll`), on
the development Mac (Apple M4 Pro). 20,000 rows of six fields (quoted
fields, a doubled quote, an empty field), parsed 10 times. Instructions
retired (`/usr/bin/time -l`), the run of a mode that only builds the text
subtracted (Xo 43 M, Go 89 M); three runs, spread under 0.5%.

| | instructions | vs Go |
|---|---|---|
| Go | 734 M | 1.00 |
| Xo before | 829 M | 1.13 |
| Xo after | 668 M | 0.91 |

(The 2026-10-21 table, regexp-time-csv-vs-go-2026-10-21.md, had 1.67x: views
and Layout work since then took it to 1.13x.)

Changes (std/native/csv.xo): the line end, the quote and the separator are
found with `scan.find_byte` (16 bytes a step) instead of a byte loop; a field
is cast to a Str (a slice of a valid text at a field boundary is valid, so the
`to_str` validation per field is gone); a quoted field with no doubled quote
is the slice itself, with no concatenation. Results are the same (csv_basic,
the ported tests of std/native/csv_test.xo).

Fields remain views of the text (decision 0330): a caller that keeps one
field of a large file calls `clone()`.

`xo bench --ab --rounds=9` (before against after, parse): instructions 0.816x
(interval 0.816 to 0.818), max RSS 0.922x; wall 0.83x with interval 0.745 to
1.18 and CPU time 1.0x are within noise at this size (a 36 ms run), so the
claim is the instruction count, not wall time.
