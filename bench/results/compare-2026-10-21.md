# Xo against LLVM, Go, and Rust on main (2026-10-21)

The owner asked for compare-2026-10-17.md's two tables again on current
main (2026-10-21), with the 2026-10-17 ratios beside each and a ranked
list of the remaining gaps to set the next codegen targets. Both tables
from main 77438548 (xo 0.23.0); the day's codegen in it includes the
amd64 speed stack, cold_saves, the generated nistec mul4, x86_not_reuse,
and scheduler step 3's loop polls (decision 0286), which both backends
now emit in every loop.

1. Linux: every workload of bench/perf/llvm/xo and bench/perf/xo,
   instructions executed on linux/amd64 and linux/arm64, native against
   LLVM.
2. Mac: bench/perf/llvm/rust.sh's Go, Rust, and Xo table.

## Method

- Linux: linux/amd64 and linux/arm64 xo cross built from main with the
  Go backend (`xo build --backend=go --targets=linux/ARCH`, std beside
  it); every program built in Docker (scripts/docker-linux.sh; amd64
  emulated) with `--backend=amd64` or `--backend=arm64` and
  `--backend=llvm`, counted with `valgrind --tool=cachegrind
  --cache-sim=no` (I refs, deterministic). Default sizes. Every row's
  checksum agrees across the four builds (the last column).
- "10-17" is compare-2026-10-17.md's own ratio (its native against its
  LLVM): LLVM's counts moved too (the runtime is Xo code LLVM compiles,
  and the loop polls are new in both), so ratios, not raw counts, are
  compared. "x86 excess" is amd64/LLVM over arm64/LLVM.
- Per function causes: cachegrind with cg_annotate on linux/arm64 for
  the largest gaps (update, hof, strings).

main since 2026-10-21) puts a preemption check in every loop, on

million on arm64 and collatz 3,889 to 4,752; arm64's sieve 1,682 to
2,111 and collatz 3,600 to 4,321. The ratios above hide it, since both
sides pay it; the Mac table against Rust and Go shows it.

## The largest remaining gaps, ranked (the next codegen targets)

Native against LLVM (Linux instructions; causes from per function
cachegrind on linux/arm64 where named):

1. update: amd64 1.32, arm64 1.26 of LLVM. Map.update's callback runs
   as a closure call (update_loop.fn1, 27 M instructions out of line on
   arm64; LLVM inlines it), and map.put costs 190 M against LLVM's 170 M
   (its inlined probe loop, rebuild out of line). Target: inline a
   closure literal passed straight to a std function that calls it once
   per element.
2. strings: amd64 1.27, arm64 1.16. The runtime's copies: memmove,
   memcpy, and libcstr.move_small take 103 M on arm64 against LLVM's 24
   M (LLVM inlines the small known length copies), num.append_int 280 M
   against 252 M, and the counting helpers (drop Str?, drop Str) 36 M.
   Target: small constant length copies inline on the native backends
   (rt.mem_copy of a length below 32 as loads and stores), then
   append_int.
3. hof: amd64 1.19, arm64 1.13. The chain's own code 95 M on arm64
   against LLVM's 50 M: each lambda a call per element where LLVM
   inlines it. Same target as update's.
4. iface: amd64 1.19, arm64 1.01: an x86 excess of 1.17 (interface
   dispatch, the indirect call's argument setup on x86_64).
5. putget, get, copymut, copyset: 1.07 to 1.18 on both: Map's put and
   get paths and the copy on write (RC helpers out of line; LLVM
   inlines rl_copy's element loop).
6. interp: amd64 1.13, arm64 0.95: x86 excess 1.19, the bytecode
   switch (a jump table's indexed load and an extra bounds check).

Xo against Rust and Go (Mac instructions, arm64):

1. The loop polls: sieve, collatz, sort, interp lost 0.11 to 0.26 of
   Rust's count each since 2026-10-17 on both Xo backends. Target:
   poll once per N iterations or hoist the poll out of loops with a
   known small trip count (Xo Lang 2's decision 0286), measured with
   sieve and collatz.
2. nbody: 2.26 times Rust's instructions (Rust's vectorized and fused
   float code; Xo's arm64 3,181 M against its LLVM's 3,036 M, so most of
   the gap is in what neither Xo backend does: fma and SIMD).
3. collatz: 1.42 times Rust's: the polls plus checked arithmetic's
   overflow branches in the inner loop.
4. sort: 1.35 times Rust's: the polls and the bounds checks of the
   inner comparisons.

Files: the Linux rows are Xo lang 4's scratch scripts (cross built
xos, inside.sh: build with each backend, cachegrind each run); the
cachegrind per function outputs were not kept.
