# List performance: in place writes for the unique owner (2026-10-08)

Goal: make `List` element writes, `push`, `pop`, and element field
updates amortized O(1) on the Go backend when the list is not shared, and
`insert`/`remove_at` no worse than a Go slice, without breaking value
semantics (core 5.1, 5.2): no copy of a list may ever observe a change
made through another copy, including lists inside structs, Maps, Options,
tuples, closures, channels, `Mutex.with`, spawned tasks, and nested lists.

Before this change every `xs[i] = x` (`rt.List.SetAt`, also `xs.set`,
`xs[i].f = x`, `xs[i][j] = x`) copied the whole list, so a loop of n
writes into an n element list was O(n^2): the sieve and sort workloads of
`bench/perf/llvm` did not finish within 60 s on the Go backend (0.1 s and
0.26 s in Go), and nbody (five structs, 25M field writes) took 18.6 s
against Go's 0.16 s. `pop` capped the capacity, so every `push` after a
`pop` copied the list too (the interp workload, a stack machine).

Host: darwin/arm64 (Apple M4 Pro), Go 1.26.1. Before: commit `f840f5e` (the
tree before this change, xo built from it). After: this change. Ratios
use each run's own Go time.

## Design

### Why the Map technique alone does not work for List writes

`Map` (`perf-map-2026-10-08.md`) never overwrites an entry another header
can see: writes append to a log past every header's view, claimed with a
compare and swap, and stale copies fork. An element write must replace a
value that other headers may be reading. Doing that soundly at run time
needs either a version check on every List read plus an undo log for
stale readers (Baker style rerooting), which also races with readers on
other tasks under Go's memory model, or knowledge of whether any other
header exists. Go copies headers silently (assignment, captures, channel
sends, struct copies), and an address based owner token does not help: a
copy at another address cannot write in place, but it still sees the
original's in place writes. So the knowledge has to come from the code
generator, as in the LLVM prototype's sticky shared flag.

### The scheme

A list is a header `{s []T, b *listBlock}`; the block of a backing array
holds `used` (the claimed length, as before: an append in place past every
header's view is always sound) and a sticky `shared` flag.

- **In place writes**: a write through a header whose block is not
  shared writes the array directly. A write through a shared (or nil,
  arena) block first copies the elements into a fresh unshared block.
  Element writes, `pop` (which now gives the slot back so the next `push`
  reuses it), `insert`, and `remove_at` (shifts, like `slices.Insert`
  and `slices.Delete`) are in place for the unique owner.
- **Own marks (generated code, `internal/gen/own.go`)**: every read of a
  binding, field, or element (Ident, SelectorExpr, IndexExpr) whose type
  holds lists is wrapped in an own mark (`(x).Own()` for a List, a
  function literal calling the generated `XoMark` methods for structs,
  tuples, Options, Results, `rt.Own` for type parameters), unless the
  expression reading it asked for a borrow. Results of std calls that
  hold lists are marked, except producers that return fresh lists and
  mark the elements they copy (`map`, `filter`, `sort`, `sort_by`,
  `reverse`, `indexed`, `keys`, `values`, `entries`, `to_list`, `split`,
  `lines`, `runes`, `freeze`). A closure marks every binding it captures;
  a value converted to an interface is marked; a `var` place that goes
  through a temporary (a user method's `var` receiver on an element) is
  marked. Because the default is to mark, a new kind of expression is
  safe without any change; a missing borrow only costs one copy on the
  next write.
- **Borrows**: reads whose copy dies before the place can be written
  again skip the mark: the base of a field or element read, the receiver
  of a read only List method, operands of comparisons, `+`, and string
  interpolation, a loop subject the body does not write, and by value
  arguments of a user function call that has no `var` parameter or
  receiver. Each borrow checks that no other operand evaluated while the
  copy is alive writes the place's root binding (`mutates`: assignments,
  `var` arguments and receivers, including inside nested blocks); `var`
  parameters may alias each other (`both(xs, xs)` is legal), so a write
  through one counts as a write through all of them.
- **Runtime marks (`std/rt/list.go`)**: `SliceRange` and `Concat` mark
  the arrays their results share; every copy of elements from one array
  into another (`copyOut`, `reverse`, `sort`, `filter`, `indexed`,
  `to_set`, Map `keys`/`values`/`entries`) marks the elements
  (`markElems`), because a list nested in those elements is now reachable
  twice. `Mutex.with` and `Map.update` mark the value they hand to the
  closure (its old copy is kept if the closure fails).
- **Nested lists are marked lazily**: marking is shallow (one block).
  While an outer block is unshared, the inner headers are reachable only
  through it; when the outer block is copied, `markElems` marks every
  inner block. A write path (`g[i][j] = v`, `g[i].push(v)`) first makes
  every list on the way the unique owner (`if !p.Mine() { p = p.Unshared() }`
  then `p.PtrM(i)`), so the inner flag can be trusted. Map values and
  boxed fields on a write path are read, marked, modified, and stored
  back.

### Soundness argument

Claim: no header observes a write made through another header.

Invariant U: a block whose `shared` flag is clear is reachable from
exactly one live header, which lives in a place only its owner's code
reads (a binding, a field or element of an owned value, or a temporary of
the generated write path).

1. U holds for every fresh block (a literal, `ListOf`, a copy, a growth).
2. A second header for a block can only be made by reading the first one
   out of its place. In generated code every such read is an own mark
   (the block becomes shared) or a borrow. A borrow's copy is used before
   the place can be written again: the `mutates` check rules out writes
   during the borrow, and the borrowed copy is never stored (storing is a
   read of the borrowed expression's own result, which is marked, or a
   call argument that the callee would have to store through an own site
   of its own: a binding read, a capture, a return, a std call).
3. In the runtime, every function that returns a header sharing a block
   marks it, and every copy of elements marks the nested lists.
4. Nested lists: an inner header stored in an unshared outer array is
   reachable only through the outer header (U applied to the outer
   block). Any path that duplicates it either copies the outer array
   (`markElems` marks it) or reads the element out (an own mark, or a
   borrow that is not written through), or goes through a write path that
   first makes the outer block unique.
5. A write in place happens only through a header whose block is
   unshared, so by U nothing else can see it. A write through a shared
   block copies first. Flags are never cleared.
6. Tasks: another task only gets a header through a closure capture, a
   channel send, `Mutex`, a scope result, or a std value several tasks
   read (Once); all of these mark (captures, std results) or receive a
   value nobody else holds (a fresh value sent is moved). So a block is
   never written in place while another task can read it. `used` is plain
   memory while a block is unshared (only its owner touches it) and
   changes only by compare and swap once it is shared; a race report on
   it means U was broken, which makes `-race` runs a check of U.

The same argument is in the comment on `List` in `std/rt/list.go`; the
marking rules are at the top of `internal/gen/own.go`.

### Generated write forms

`SetAt` and `M_push` with their copy calls inside are over Go's inlining
budget for generic shape instantiations (cost 113 and 179, budget 80),
and their pointer receivers keep a local list in memory. Generated code
uses small value receiver methods that each inline:

```
if !xs.Mine() { xs = xs.Unshared() }
xs.PutM(i, x, "main.xo:13:9")            // or p := xs.PtrM(i, at) for xs[i].f
if xs.CanPush() { xs = xs.PushFast(x) } else { xs = xs.PushSlow(x) }
```

A field read of an element (`bs[i].x`) uses `bs.RefM(i, at).F_x`
instead of copying the element out (`AtM`): Go keeps only structs of up
to four fields in registers, so copying a seven field Body cost a memory
copy per read (nbody 0.68 s with `AtM`, 0.25 s with `RefM`). Go may load
the field after a later call in the same expression, so `RefM` is used
only when the statement or condition being generated cannot write the
list.

## Limitations and next steps

Ranked by expected gain.

1. **The sticky flag never clears**: after any copy, the next write
   copies even if the other copy is dead. The common case is a function
   that builds a list and returns it (`return xs` marks). Next
   experiment: treat `return x` of a local, non parameter binding of a
   function without `defer` as a move (no own mark); measure with a
   `build then write` workload in `bench/perf/xo/main.xo`.
2. **Repeated uniqueness checks**: each write repeats `Mine()` (a load
   of the block and an atomic load); nbody does 12 per inner step and is
   1.58x of Go. Next experiment: a per straight line region cache in
   `fnGen` (as the LLVM backend has) that skips `uniqueList` for a place
   already made unique when nothing in between can mark it (no own read
   of its root, no call); measure on `bench/perf/llvm/xo/nbody`.
3. **Lists inside Maps, Mutexes, and boxes** are always copied on a
   write through them (`m[k][i] = v`, `Map.update` and `Mutex.with`
   closures that write elements, recursive structs): O(len) per write.
   `push` through them stays O(1) (the claim). Next experiment: let
   `Map.update` skip `MarkP` when the map's entry was appended after the
   last copy of the map (the Map already knows its claimed log length),
   and roll back a failing `Mutex.with` from a copy made only on its
   first element write.
4. **`--no-mono` generic code** marks type parameter values through
   `rt.Own`, whose interface call makes the value escape (one allocation
   per own read). Next experiment: per instantiation mark functions in
   the dictionary (`rt.MarkFn[T]` cached in a `sync.Map` keyed by
   `reflect.Type`), measured with `MONO=1 bench/perf/run.sh`.
5. **Growth**: lists double on growth; Go's 1.25x for large slices uses
   30 percent less peak memory on sieve. Next experiment: use
   `append`'s growth (`slices.Grow`) in `copyOut` and compare `sieve` RSS
   and time.
