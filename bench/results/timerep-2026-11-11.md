# Time representation: one word against Go's two (2026-11-11)

Decision 0614's measurement. bench/perf/timerep runs the same workloads with
`const WIDE` false (A: Xo's `Time`, one Int of nanoseconds since 1970) and
true (B: a two word struct, seconds since 0001-01-01 and nanoseconds, with
Go's Time.Add and Time.Sub normalization, derive Eq, Ord). Checksums are the
same for both. linux/arm64 host 1, `xo bench --ab --rounds=10`, built by
lang3-protosz2's xo (33b87c901).

| workload | A wall | B wall | B / A (95%) |
|---|---|---|---|
| now (4M clock reads) | 56.84 ms | 63.99 ms | 1.126 (1.101 to 1.222) |
| add (80M `t + d`) | 21.7 ms | 62.88 ms | 2.897 (2.719 to 2.938) |
| sub (80M `a - b`) | 59.68 ms | 95.91 ms | 1.607 (1.595 to 1.646) |
| sort (200k times, 5 sorts) | 46.31 ms | 65.11 ms | 1.406 (1.363 to 1.426); max RSS 1.434 |
| format (1M RFC 3339 texts) | 66.49 ms | 67.26 ms | 1.012 (0.987 to 1.03), within noise |

What the proxy over and under states:

- B is a user struct; a builtin two word Time would pass in two registers the
  same way, so the normalization branches of add and sub (a carry between the
  words) and the doubled size are the cost that would remain.
- now: B splits the one word reading into seconds and nanoseconds (a
  division); a real wide Time would take clock_gettime's two fields
  directly, so 1.126 is an upper bound, and the true cost is near zero.
- format is dominated by the digits; the representation only changes how
  the day and the second of day are found.
- Not measured, and costlier than any row: `Atomic[Time]` (a 16 byte
  compare and swap or a lock), and every Time in a struct, a List, a Map key
  or a channel slot doubling to 16 bytes (sort's RSS row).
