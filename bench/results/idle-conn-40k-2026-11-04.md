# Idle connection memory at 40,000 (2026-11-04)

bench/perf/idleconn (client, goserver, xo), linux/arm64 host 2, one run each,
`ulimit -n 200000`, 10 s settle, 3 loopback source addresses (127.0.0.1 to
127.0.0.3) so the source ports do not run out. RssAnon of the server after
the connections are held, minus its RssAnon before; every connection also
answered a second request.

## HTTP/1.1, 40,000 connections

| Server | RssAnon before | RssAnon held | per connection | threads | mappings |
|---|---|---|---|---|---|
| Xo (std/http) | 652 kB | 252,024 kB | 6.3 KB | 22 | 582 |
| Go net/http | 2,916 kB | 774,028 kB | 19.3 KB | 21 | 128 |

Xo holds a connection in 33% of Go's memory (the 0.36 notes' 5,000 connection
figures were 8.1 against 15.7 KB; the 2,000 connection sanity run on the same
host gave 9.7 against 24.5 KB). Both servers answered every second request.

## TLS with HTTP/2, 40,000 connections

One transport per connection, 3 source addresses (a first run with one
source address failed 39,986 of 40,000 on both servers: the client ran out of
source ports, not a server fault).

| Server | RssAnon before | RssAnon held | per connection | threads |
|---|---|---|---|---|
| Xo (std/http, TLS) | 908 kB | 645,448 kB | 16.1 KB | 22 |
| Go net/http | 4,600 kB | 1,632,836 kB | 40.8 KB | 24 |

Xo holds a TLS h2 connection in 39% of Go's memory (the 0.36 notes: 16.0
against 48.6 KB at 5,000 connections); all 40,000 completed on both.
Single runs on host 2; the interleaved n=3 method of the THP notes was not
repeated at 40,000.
