# SHA-512 and Rand in Xo (zero-C audit B08), 2026-10-14

Work item B08 of `zero-c-audit-refresh-2026-10-13.md`: xo_crypto.c's
SHA-512 (FIPS 180-4) and the Rand capability move to Xo.

## What moved

- **SHA-512**: `digest_tables.sha512_block` (generated by internal/llvm
  TestDigestTables beside SHA-256: 80 rounds unrolled, the schedule in 16
  locals, the working variables renamed, the constants immediate, whole
  64 bit words with `rt.int_wrap` rotations) reads a block at an address;
  `digest.sha512_3` streams up to three memory ranges and pads.
  std/native/llrt/cabi_crypto.xo exports it as `xo_x_sha512_3`, which the
  C Ed25519 calls through its unchanged `cr_sha512_3` (decision 0204).
  cabi_crypto.xo is a feature module: std/native/crypto.xo imports it, so
  only programs that use std/crypto carry SHA-512. Every program links
  xo_crypto.c, so the C has a weak `xo_x_sha512_3` that faults; a program
  with std/crypto overrides it (checked on Mach-O with both backends; ELF
  and COFF honor weak definitions the same way, Windows not yet run).
  Deleted: the C SHA-512 (state, constants, block, write, sum,
  cr_ror64, cr_be64), 129 lines (a2a7d6be lines 113-114 and 153-279).
- **Rand**: std/native/llrt/rand.xo. `Rand.int`, `float`, `bool`, `bytes`
  lower to the native prelude's `llrt_rand_*` (selfhost/ssa
  `rand_rt`; a WASI module keeps the wasm runtime's `rt.rand_*`). The
  system generator is linux.xo `random` (getrandom), darwin.xo
  (getentropy), windows.xo (BCryptGenRandom); in a test binary the test
  world's seeded PCG through two C exports of xo_testing.c,
  `xo_tw_seeded` and `xo_tw_rand_u64` (the state stays with the test
  world, item B14). The same draws as the C: one word per `int` try
  (rejection above `MAX - MAX % span`), the top 53 bits for `float`, the
  low bit for `bool`, one draw per byte for seeded `bytes`. os.CreateTemp's
  names (fspath.xo) take `rand.next_u64()`; `xo_fs_raw_rand` and its
  rt.xo declaration are deleted.
- **Kept for the seed**: xo_crypto.c's `xo_rand_int`, `xo_rand_bytes`,
  `xo_rand_float`, `xo_rand_bool` and their entropy (95 lines) and
  xo_win.c's `xo_w_entropy` stay as a labeled seed compatibility block:
  the prebuilt seed 0.9.0-5e21dc31 still lowers Rand to them while it
  builds this checkout's xo (gotchas/runtime-c-the-seed-still-calls.md).
  No program the new xo builds calls them; they go once the seed is a
  release with B08.

xo_crypto.c: 763 to 647 lines.

## Performance (decision 0180's bar)

bench/perf/digest gained `ed25519_big` (200 Ed25519 signatures of a 64
KiB message: SHA-512 of 25 MiB, the message hashed twice a signature)
and `ed25519_small` (the same signatures of a 32 byte message: the rest
of the signature). SHA-512's cost is big less small. Instructions
retired (`/usr/bin/time -l`, the minimum of 5 runs) on the shared Mac
(darwin arm64, other agents running), `bench/perf/digest/measure.sh`
with `WORKLOADS="none ed25519_big ed25519_small"`. C: main at a2a7d6be
(before B08); Xo: this branch at a13294f2 (B08 merged with main
da6a55c1; `ed25519_small`, which hashes almost nothing, is the same on
both, so the base's change does not touch these programs).

## Correctness

- TestCryptoDiff (internal/llvm/crypto_diff_test.go): crypto_diff.c now
  links the exports of a program that uses std/crypto (`cOnlyWith`), so
  its `sha512` lines (the FIPS 180-4 examples and lengths 111 to 1000
  around the block and padding boundaries) and every Ed25519 line run the
  Xo SHA-512: 4,086 operations agree with Go (-count=1, not -short).
- Goldens (scripts/selfhost-goldens.py with the branch's xo): 180 of 180
  on arm64 and 180 of 180 on LLVM (native_ed25519, native_crypto,
  fs_native's temporary files among them).
- Seeded Rand: cmd/xo/testdata/nogc/same "seeded rand" logs `a=403839
  b=297188 bytes=b20e40b6 f=true` on the Go backend, arm64, and LLVM;
  TestNoGCTests/same passes.
- System Rand on arm64 and LLVM: `int(-3, 7)` covers all 10 values in
  1,000 draws, bool and float balanced, `bytes(-1)` empty, the full Int
  range draws, and `int(5, 5)` faults `rand.int(5, 5): the range is
  empty at main.xo:22` as the Go backend does.
- TestSelfhostWasm and the fixed point: see the B08 row of the audit.
