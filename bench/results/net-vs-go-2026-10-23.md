# Xo against Go, network rows: re-measure (2026-10-23)

Re-measures of the rows `net-vs-go-2026-10-22.md` showed below 1: TLS bulk
(AES-GCM, ChaCha), h2 download, WebSocket echo, CRUD mixed, and a sweep of
the HTTP/1.1 server rows. This file replaces the 10-22 gaps for those rows.

## Method

- Machine: Mac, Apple silicon arm64, 24 GB, macOS (Darwin 27); Go 1.26.1;
  Xo built from main 9333bb71d (native arm64 backend, default flags).
  Docker rows: linux/arm64 containers on the same Mac.
- Load at the start of each run: 5.0 (HTTP sweep), 5.7 (TLS/h2 first run),
  5.2 (TLS/h2 confirm run, WebSocket), 5.7 rising to 23 (CRUD mixed,
  Docker). The machine was not quiet; other agents ran. Reps are
  interleaved (Xo, Go, Xo, Go ...) so a load burst hits both alike, and
  every row reports its reps, not only a median.
- TLS and h2 rows: `bench/perf/tlsrate/native.sh` (Xo server and Go server,
  one client), 3 reps then a confirm run of 5 reps. Ratio = Xo throughput
  over Go throughput (above 1 is Xo faster).
- WebSocket: `bench/perf/netgo/ws` client, echo of 64 B, gorilla server
  against Xo's server, 5 interleaved reps of 4 s, msgs/s.
- CRUD mixed: `bench/perf/http/listlock-docker.sh` (the users CRUD API of
  `bench/perf/http`, Go and Xo servers), Docker linux/arm64, 5 interleaved
  rounds of 10 s, 1024 connections, rps and server CPU per request.
- HTTP/1.1 server sweep: Go twins of the plain, item (GET one), items (GET
  list), echo (POST body back) and router (path parameters) server rows,
  one Xo and one Go program each, 64 connections for 5 s from a Go load
  generator, server CPU from `ps` cputime per request, 3 interleaved reps.
  Rps here is bound by the client near 110 to 125k, so the CPU per request
  is the signal.

## CRUD mixed (Docker linux/arm64, 1024 connections, 10 s rounds)

| | Xo | Go | Xo / Go |
|---|---|---|---|
| rps, median of 5 rounds | 131k | 123k | 1.06 |
| server CPU per request, us | 20.8 | 23.8 | 0.87 |

Per round Xo rps: 142k, 131k, 135k, 82k, 82k; Go: 93k, 123k, 95k, 134k,
130k. Rounds 4 and 5 ran at load 18 and above and both servers fell. This
run was NOT quiet (load 5.7 at the start, 23 at the end); the 10-22 figure
of 0.93 was under load too. A quiet rerun would tighten the ratio; it
would not hide a gap of 0.9. The first attempt was invalid: DURATION must
be `10s` (a bare `10` made loadgen exit silently, and the script discards
its stderr).
