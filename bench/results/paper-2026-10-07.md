**Headline:** with the spec in context, agents followed every rule the spec
states. All the risk is in what the spec does not state. A paper test cannot
measure compile iteration cost, so the proposed decisions are not settled by
this; stage 2 (real `xo check`) is needed for that.

## Spec bugs (contradictions, not just gaps)

1. **Appendix A route strings interpolate.** `"GET /users/{id:Int}"` is
   interpolated under section 1.6. Fixed in the appendix by using `r"..."`;
   whether route patterns deserve a non interpolating syntax is open.
2. **`use std/test` binds a keyword.** The default local name `test` is a
   keyword, forcing `as t`.
3. **Cancellation cannot be a value (7.2), but tasks need `Cancelled` errors.**
4. **`ok err some none` are lowercase but act as variants**, contradicting 1.5
   (variants are `UpperCamel`). Being predeclared and unshadowable, they also
   take the names `err` and `result` from user code (task 02 had to rename).
5. **`uses a, b` inside a parameter list is ambiguous** with the parameter
   separator: `f: fn(Job[T]) -> R ! E uses net, clock,` (task 02).
6. **`std/log` performs output with no capability** (Appendix A), against
   section 6.3.
7. **A `pub` pure function cannot be written explicitly**: `pub` requires a
   `uses` clause and there is no empty form.

## Friction (rule followed, but costly)

1. **Value semantics: get, modify, put.** Updating a map entry is
   `var b = m.get(k) ?? new; b.take(now); m.put(k, b)` inside `Mutex.with`.
   Forgetting the `put` silently loses the update, and nothing in the spec
   catches it. Collecting results from workers needs a `Mutex[Map]` and a
   reorder pass. Counters in closures need `Atomic`.
2. **Effects leak into types.** A reusable pool or middleware cannot be generic
   over its callback's effects, so `clock` was added just so tests could sleep.
3. **Structured concurrency and daemons.** An infinite background task in a
   scope makes the scope wait forever unless cancelled by hand.
4. **No `_` plus unused binding errors plus mandatory result handling** force
   awkward code in cleanup paths (`let _ = dst.remove(tmp)`).

## Proposed spec changes (need a decision each)

1. Explicit failure: `return err(e)` and tail `err(e)` (or a `fail e` form).
2. `_` wildcard pattern and `_` prefixed names exempt from XO0110; parameters exempt.
3. Rename `ok err some none` to `Ok Err Some None`, freeing `err` and `result`
   for user code and matching both the naming rule and model priors. Make
   `result` contextual (only inside `ensures`).
4. Effect variables: `fn run_pool[T, R, E, fx](f: fn(T) -> R ! E uses fx) uses net, fx`,
   plus subsumption (a less effectful function is accepted where more are allowed).
   Wrap effect lists in a function type in parentheses: `uses (net, clock)`.
5. Scope rules: early exit from a scope body cancels children; `s.spawn_background`
   for daemons that are cancelled when the body finishes; a `scope ... timeout`
   expression yields `T ! Canceled`.
6. Cancellation surfaces as `Canceled` from blocking calls that already return
   a `Result`; infallible blocking calls still unwind.
7. `Map.update(k, default, fn(var V) -> R) -> R` and a compile error when a
   mutated `var` is never read afterwards (`XO0520`, lost update).
8. Tests: `test` blocks have an implicit `os: TestOs` with `os.clock.advance(d)`,
   `os.net.handle(...)`, `os.fs` in memory. Rename `std/test` to `std/testing`.
9. Logging requires `stdio` (or a `log` capability from `Os`).
10. A stdlib surface spec (`spec/std.md`) for http, json, fs, time, task, testing.
