# XO_THP=dense: Go's density rule on Xo's heap (2026-11-02)

Follow-up to [thp-density-2026-11-02.md](thp-density-2026-11-02.md), which found Go stays
low under THP `always` because its page heap fills the 2 MiB regions it touches (71-89%),
where Xo's per thread 4 MiB bump and page chunks fill 13-23%. This tries the cheap half of
Go's rule on Xo's chunks, with no default change (decision 0448 case (c), the lead's option 4).

Branches, unpushed (Xo Lang 2):

- `l2-dense` v1, c5b88569a: `XO_THP=dense` advises every bump and page chunk
  MADV_NOHUGEPAGE at map time, and a chunk the heap record has used up MADV_HUGEPAGE
  (khugepaged may collapse it later). 4742161bd makes dense the default, for measuring only.
- `l2-dense2` v2, c8fe48019: as v1, but once a record has used up one chunk its next chunk
  is advised MADV_HUGEPAGE as it is mapped, before its pages fault, so a busy record's later
  chunks get huge pages at once and its first chunks never do. fa9f2a103 makes it the
  default, for measuring only.

AnonHugePages in MB after 15 s. hg counts the mappings whose VmFlags carry `hg`.

| amd64 WSL, always for the run | 109, 121, 113 / 92-104 | 56, 65, 63 / 24-32 | 55, 61, 51 / 18-28 | 50, 64, 54 / 16-30 | 86, 88, 86 / 72-78 |
| linux/arm64 host 2, always (v1 run) | 88, 74, 95 / 40-60 | 45, 46, 48 / 14-18 | 44, 48, 44 / 12-18 | | 83, 89, 87 / 70-80 |
| linux/arm64 host 2, always (v2 run) | 36, 35, 58 / 6-28 | 45, 46, 43 / 14-16 | | 39, 47, 39 / 8-18 | 80, 76, 74 / 56-76 |

The WSL row set THP to `always` for the run only, with the owner's approval of
2026-11-02, and set it back to `madvise` in the same job
([thp-always.sh](thp-dense-2026-11-02/thp-always.sh), a trap on exit; the log reads
`always [madvise] never` after). Host 2 is fragmented and its huge page supply moved
between the two runs (Xo default 74-95 then 35-58), so compare columns within a row.

No Xo run had a single `hg` mapping: at 2,000 idle connections each thread uses about
260 KiB of its chunks, so no chunk is ever used up and dense is XO_THP=off for this
server. Off leaves 14-32 MB of huge pages (the mappings made before XO_THP is read,
thread stacks, the TLS block).

## Reading

- v1 costs what XO_THP=off costs (off: self CPU +7.5%, decision 0454): advice after a
  chunk is used up comes after its pages faulted, so it does not bring huge pages back.
- v2 keeps the self build's wall on the always host and costs coll's edit about 4% for
  21% less RSS; on a madvise host (most distributions' default, and WSL) its HUGEPAGE
  advice is new and coll's edit runs 5% faster for 7% more RSS.
- Neither changes an idle server: Go's other half, one address ordered page heap whose
  touched regions are full, is what keeps Go both fast and fairly low, and it is the
  large change (candidate 1 in thp-density-2026-11-02.md).
- Next: rerun v2's self build unloaded on both hosts, then a variant that cuts coll's cost
  on always hosts, then an ADR (Proposed) for the owner.
