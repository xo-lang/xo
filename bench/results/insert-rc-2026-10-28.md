# insert_rc: data structures, not the algorithm (2026-10-28)

Reference counting insertion (compiler/ssa rc.xo, `Rc.rc_func`) was the
compiler's largest single cost: 30 percent of a cold self build's CPU in
decision 0274's profile. This file is the profile of main e60ac26f2, what
it showed, and the changes that followed, each proved by output
identity.

Setup: the cold self build of xo (`cd compiler && XO_BACKEND_CACHE=off
XO_FE_CACHE=off XO_BIN_CACHE=off XO_PROF=cpu xo build --backend=arm64
--phase-times ./xo`) on the development Mac (darwin/arm64, 24 GB),
shared with other agents' jobs, so shares are the measure, and
`/usr/bin/time -l` instructions retired decide the A/B (stable under
load; wall and cycles were not).

Wall phases: insert_rc 7.15 s, inline 5.1, emit 15.5, check 1.25, ssa 1.9.

Not algorithmic: liveness is a worklist, the walk is linear in the
instructions, chain_pads is windowed. The cost is data structures and
allocation: string-keyed sorts, Leaf structs (with a path Str) copied
through maps, sorts and lists, lists grown by push, and RC operations
materialized then cleaned (remove_dead_fields, group_releases).

On an edit insert_rc does no RC at all (every function reused from the
cache, undecoded): the HTTP server's edit spent 60 ms of 520 in
insert_rc, all keying (plan 28: rc_key's SHA-256 per function; borrows
15: the body hashes; read 9; apply 16; uniq_var_params 9); fib's 24 of
220. Three full-body hash passes per edit (borrows, rc_key, inline.keys:
70 ms on HTTP) are the edit lever, to be re-measured under separate
compilation (XO_SEPCOMP), where std's functions are not hashed.

## The changes

1. `sorted_leaves`: one Int key `(root * R + rank(path)) * n + i` and
   the Int pdqsort, the paths' ranks kept beside the interned paths
   (`path_ranks`); no string compared, no key tuple, each Leaf moved
   once. (A first version sorted equal-root runs by path with an
   insertion sort: 21 s, quadratic on a struct's many leaves.)
2. The walk's lists: `edge_code` removes the block's pre-code list from
   the map before appending (a get and push copied it on every edge);
   `Counted` is one map of packed counts instead of two; the walk's,
   insert's and the use and leaf lists are made with their capacity.
3. `remove_dead_fields`: use counts and a worklist in one pass, only
   blocks with a dead read rebuilt (the fixed point rescanned and rebuilt
   every block each round).
4. Liveness sets as `Set[Int]` of leaf keys with one leaf table per
   function: tried, no gain (the table and a rebuilt map for the sort
   cost what the Leaf puts saved), dropped.
