# xo1 against every golden suite, 2026-10-12 (decision 0178)

How much of `xo build` the self hosted driver xo1 (`selfhost/xo`)
replaces today. xo1 is built by the Go compiler with `--backend=arm64`
(A; its assembly is the fixed point's, decision 0174). Apple M4 Pro,
macOS, about ten other agents' work on the machine, so the wall clock
figures are noisy; the counts are what matters. Script:
the scratchpad's measure.sh and measure2.sh, which run the commands
below in order through the shared heavy lock.

## Run 1: main fdda92f plus `xo1 --backend=llvm` (commit 497a170)

| step | command | result |
|---|---|---|
| build A | `.tools/xo build --backend=arm64 -o A selfhost/xo` | 232.4 s wall clock |
| fs_files (file handles, copies, links; decision 0172) | `A build --backend=arm64` and `--backend=llvm` of internal/gen/testdata/golden/fs_files, run | both build and print want.txt's stdout |
| arm64 goldens | `selfhost-goldens.py A` | **157 of 157** (43.8 s) |
| the same with LLVM | `XO1_BACKEND=llvm selfhost-goldens.py A` | **157 of 157** (46.9 s) |
| Go backend goldens | `selfhost-gogoldens.py A` | **96 of 133** (30.0 s) |

The arm64 golden set is 132 programs of internal/llvm/testdata/golden
(want.txt, no allocation live at exit) and 25 of
internal/arm64/testdata/run (against the Go backend's output); it has
grown from 147 since decision 0174.

The 37 Go backend failures, by cause:

| programs | cause |
|---:|---|
| 27 | the `test_` programs: xo1 had no `test --backend=go` |
| 8 | `use go` of standard packages (go_hex, go_regexp, go_sha256, go_strconv, go_strings, go_url; gc_config: runtime/debug; arena_holes: sync): xo1 did not copy the binding adapters (`rt/xo_gobind_<path>.go`) into the build tree, so `rt.Hex_encode_to_string` and the like were undefined |
| 1 | go_uuid: a third party `use go` package (adapter and the binding workspace's go.mod requirements) |
| 1 | go_callback_deadlock_real: `use go` with callbacks (adapter, and the `xo_gotimers` tag with -checklinkname=0) |
