# xo1 against every golden suite, 2026-10-12 (decision 0178)

How much of `xo build` the self hosted driver xo1 (`selfhost/xo`)
replaces today. xo1 is built by the Go compiler with `--backend=arm64`
(A; its assembly is the fixed point's, decision 0174). Apple M4 Pro,
macOS, about ten other agents' work on the machine, so the wall clock
figures are noisy; the counts are what matters. Script:
the scratchpad's measure.sh and measure2.sh, which run the commands
below in order through the shared heavy lock.

## What the suites do not cover

`xo1` is still one directory per build, the host only on the Go
backend, and has none of `--race`, `--holes`, `--no-mono`,
`--no-arenas`, `--release`, `--ci`, `--seed`/`--explore` on the Go
backend's tests, `--record`, the binary cache, split LLVM builds,
`--real` tests, regressions_test.xo, or the check's diagnostics in its
own output (decision 0178 lists them as stage 1).

## Stage 4: the module commands (cli-modules, 2026-10-12)

`selfhost/cli/modules` (Xo) ports `xo get`, `xo mod tidy`, `xo mod
accept-effects`, `xo mod clean`, `xo mod proxy serve`, and `xo vendor`
with fetching (git, the module proxy client, the checksum log client with
Ed25519 from std/crypto, decision 0189). xo1 dispatches these commands to
it; `xomod` (selfhost/cli/modules/xomod, built with `xo build
--backend=arm64`) runs them alone and hands every other command to the Go
`xo` ($XOMOD_FALLBACK), so cmd/xo's tests measure the module commands in
Xo while the other stages are not merged. Branch commit bc72f16, `-short`.

7 of 9 module tests pass against xomod. `TestModulesXoSame`
(cmd/xo/modules_xo_test.go) runs 37 steps in 2 module worlds (the
internal/mod fixtures; an effect lock world with a `use go` hatch) with
internal/mod in process and with xomod, each on its own app copy and
module cache: exit status, standard output and error (paths normalized),
xo.mod, xo.lock, vendor/, and every cached module tree (files, modes,
`h1:` hashes) are byte identical after all 37 steps.

Pending: `xo publish` and the API changes `xo get` prints (after the
stage 3 port of internal/release), `xo audit` (in progress), and the same
tests against xo1 once the stage 2 commands are merged (xo1 runs only the
module commands from this branch).
