# xo1 against every golden suite, 2026-10-12 (decision 0178)

How much of `xo build` the self hosted driver xo1 (`selfhost/xo`)
replaces today. xo1 is built by the Go compiler with `--backend=arm64`
(A; its assembly is the fixed point's, decision 0174). Apple M4 Pro,
macOS, about ten other agents' work on the machine, so the wall clock
figures are noisy; the counts are what matters. Script:
the scratchpad's measure.sh and measure2.sh, which run the commands
below in order through the shared heavy lock.

## What the suites do not cover

`xo1` is still one directory per build, the host only on the Go
backend, and has none of `--race`, `--holes`, `--no-mono`,
`--no-arenas`, `--release`, `--ci`, `--seed`/`--explore` on the Go
backend's tests, `--record`, the binary cache, split LLVM builds,
`--real` tests, regressions_test.xo, or the check's diagnostics in its
own output (decision 0178 lists them as stage 1).

## Run 6: switch point A on (commit f45a4cc, the gate)

The released `xo build|run|test` for native backends runs xo1
(internal/selfdriver), built by `xo` from its embedded sources. Since
run 5: native test binaries list contract fuzz tests as skipped,
selfhost/ssa attributes a dependency's log records (`log_from`, decision
0173), and xo1 hands a program it cannot lower back to the Go driver
(XO1201 diagnostics). Script: the scratchpad's gateA.sh, through the
shared heavy lock.

| step | command | result |
|---|---|---|
| xo1 from the embedded sources (first native build) | `.tools/xo build --backend=arm64 -o arith-A internal/llvm/testdata/golden/arith` | 290.4 s wall clock (xo1 built into the user cache, then the program) |
| cmd/xo, full, switch on (the default) | `go test -p 1 -parallel 2 -count=1 ./cmd/xo` | **ok** (69.0 s) |
| internal/build, full, switch on | `go test -p 1 -parallel 2 -count=1 ./internal/build` | **ok** (63.8 s); its tests call internal/build directly, so the switch does not change them |
| same binaries | `selfhost-samebin.py <xo1 of the cache>` | **159 of 159 identical** (39.9 s) |
| fixed point | `selfhost-switchover.sh` (A: the Go compiler with `XO_SELF_DRIVER=0`; B: A compiles selfhost/xo; C: B compiles it) | **G.s == B.s == C.s** (14,821,960 bytes of assembly; the B and C binaries differ, their files have different names); B runs the arm64 goldens 159 of 159 |

Wall clock: A 232.1 s, G (`xo asmdump`) 197.6 s, B 368.5 s, C 366.6 s,
with about ten other agents' work on the machine.

The 18 tests of run 5 again with every `build`, `run`, and `test` through
the xo1 of run 6 (`XO_SELF_DRIVER_ALL=1`, no fallback to the Go driver):
**12 of 18** pass (42.6 s). TestLogAttribution and the native listing of
TestNoGCTests now pass; the six failures are `--ci` (TestBuildCI,
TestBuildRelease, TestModules), XO1201 (TestBuildRunLLVM, TestNoGC), and
`--real` on native tests (TestNoGCTests's real case). With the switch as
released those commands do not reach xo1 alone: `--ci` and `--real` stay
with the Go driver, and a program xo1 cannot lower falls back to it, so
cmd/xo's full suite passes (the table above).
