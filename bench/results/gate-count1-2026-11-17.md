# Gate and pushq `-count=1` audit (task #251, 2026-11-17)

The owner asked (2026-11-17) that gates use the caches: each `-count=1` in
scripts/gate.sh (11) and scripts/lead/pushq.sh (7) kept only with a
reason. Go's test cache keys a result on the test binary, the environment
variables the test read and the files the test process itself opened or
stat'ed. It cannot see files read by a child process.

## Go test calls: all kept

Every package these calls test (internal/repotest, internal/xotool,
internal/selfhost, internal/arm64, internal/llvm, internal/stdtest, cmd/xo)
runs a child process (bin/xo, bash, python3, git or go) that reads the
repository: 15 to 50 test files a package call exec.Command. A cached pass
would miss a change to std, compiler/ or a script those children read.
Gates also run in a fresh tree at a new path with XO_CLI pointing into
it, so the cache would rarely hit there in any case.

| File:line (2026-11-17) | Call | Child process reads |
|---|---|---|
| gate.sh `full` (330) | every go test step | bin/xo builds of goldens, std |
| gate.sh 654, 753, 804 | TestGoldenIRManifest | bin/xo LLVM IR |

| pushq 742 | TestGoldenRun | bin/xo builds |

## xo test calls: two changed

xo's own run cache (decisions 0439 and 0701) keys a run on what each
test build read, so it can replay safely:

- stdfast: `xo test --count=1 --std-module=M` is now
  `xo test --since=BASE --std-module=M` (only the tests the change
  reaches; an unchanged module replays).
- xounit: `xo test --count=1 compiler/...` is now `xo test compiler/...`.
- stdwasm keeps `--count=1`: its runs go through XO_TEST_EXEC (node), a
  runner that is not part of the run cache's key.
