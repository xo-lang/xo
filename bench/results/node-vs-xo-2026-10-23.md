## Notes

- Not a quiet machine: other agents' jobs ran during the measurements. Every row waited for the 1 minute load average to drop under 5 and reports the load it started at; `--ab` alternates the two programs each round, so treat ratios within 10 percent as ties.
- Every program prints a checksum and the runner stops when Node's and Xo's differ; the CRUD server was checked against the Go server on 26 requests by bench/perf/http/parity.sh.
- Node is measured the way Node is used: one process for the CRUD server (a cluster of workers would give each worker its own in-memory store, so it is not the same program), async tasks on the event loop for spawn, fanout and pingpong, worker_threads with a SharedArrayBuffer and Atomics for mutex and pmap. There is no rwmutex row: Node has no read write lock, and writing one from Atomics would measure that code.
- Wall, instructions and RSS include Node's start (about 40 ms), which is a large part of the short rows; the fib and pmap rows are long enough to show the engine.
