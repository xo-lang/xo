# bigmod: two rows of mac_row in one pass (negative result)

Date: 2026-10-26. Xo Lang 1. Machine: the development Mac (arm64).
Measure-class `xo bench --ab`, 20 rounds, N=30, one xo: A built with the
parent's std (XO_STD), B with this std, so the pair differs only in
std/native/llrt/bigmod.xo. The branch is kept as
`refs/recover/lang1-mac-row2` (8e2c2a4b8), not on main.

## Question

Native RSA sign4096 is about 2% behind LLVM. mac_row is about 88% of the
time on both backends. Four changes to where mac_row stores its words
each cut instructions and lost wall time at 4096 bits. Loop head
alignment gave 0.4%. Store-to-load forwarding was disproven.
(~/xo-lead/notes, parked README.) What remains is the dst traffic: each
row loads and stores all n words of dst. Does one pass over two rows
(Go's addMulVVWW idea) help, so that each dst word is loaded and stored
once for both rows?

## Change

`mac_row2(dst, src, k0, k1, len)`: dst[p] += src[p] k0 + src[p - 1] k1
for p in 0..len + 1, with a two-word carry (the high word 0 or 1).
prod_at pairs its rows i and i + 1 and runs mac_row on an odd last row.
The loop is not unrolled and tests for the top word in each step.
redc_at and square_at are unchanged. Results are correct: every sign and
verify checks, 3 of 3.

## Results (B / A)

| row | wall | instructions | cycles |
|---|---|---|---|
| sign4096 | 1.052 (1.05 to 1.055) | 1.051 | 1.052 |
| sign2048 | 1.054 (1.046 to 1.06) | 1.040 | 1.056 |
| verify4096 | 1.013 (noise) | 1.028 | 1.019 |

The bench's __text grew 176 bytes.

## Why

The pass did not trade instructions for memory. It added them: each word
needs three carries into the two-word carry and the top-word test, which
outweighs one load and one store saved per word. Wall time follows
instructions here. The 4096-only penalty that defeated the store
changes did not show, because this variant loses at both sizes.

## Next steps, ranked

1. An unrolled mac_row2 with the top word peeled out of the loop and
   the carry kept in flags across a pair (adcs chains, as mac_row does
   now). It would need to be at or below mac_row's instruction count
   per word for two rows before measuring again.
2. A toy mac_row loop over a 66-word buffer with the same row shift,
   timing store placements, to find what the M-series penalizes at 4096
   bits only (idea b of the parked notes), before another code shape.
3. Leave RSA at about 2% behind LLVM at 4096 bits and level at 2048
   bits.
