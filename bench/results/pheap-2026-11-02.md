# Page heap (decision 0457) prototype, 2026-11-02

A shared, address ordered page heap (Go's mheap) for Xo's large blocks, page
blocks and the threads' bump runs, built in stages on unpushed branches (Xo
Lang 2). Summary: under THP `always` it halved an idle TLS server's memory
and put it below Go, but decision 0456's v4 (landed the same day) gets the
same server lower on its own, and the page heap costs the self build 1 to 6%
wall and up to 17% max RSS on Linux. Not landed; what each stage measured
follows.

## Mac self build (darwin footprint, same xo, XO_PHEAP=0 against 1)

Off 3.62-3.69 GB, on 3.99-4.15 GB with every variant tried. The page heap's
sys time is 3 s against 12 s off: the default unmaps freed blocks over 16
KiB eagerly. Splitting by part: large blocks only +150 MB, page blocks only
+10 MB, all +450 MB; free resident pages stayed under 70 MB, so the excess
is in pages handed out (reused dirty runs). Advising only touched pages, and
releasing every given run at once, did not close it.

## Why it costs

- Churn: the scavenger released 13-16 GB over one self build (2,900
  scavenges), most faulted in again; a tighter goal cut max RSS and cost wall.
- The early prototype took the switch's lock on every refill, and searched
  fragmented chunks bit by bit (Mac self build 103 s, 48.7 with a hint, 32
  with PT_MAX).

## Correctness

TestGoldenRun with XO_LEAKCHECK (including the thread goldens), TestRun and
TestGoldenRun under XO_RC_CHECK pass on linux/arm64 at stage 4; Xo Lang 1's
stress program (now golden pheap_stress) is clean on linux/arm64 and darwin.
