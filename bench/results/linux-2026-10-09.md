# Linux validation (2026-10-09)

First build and run of everything Linux specific: the Go backend's test
suite on Linux, the LLVM and arm64 backends' output linked as ELF and run,
the native runtime's Linux paths (epoll poller, futex parks, signals, TCP,
HTTP), and the x86_64 fiber switch.

## Setup

- Host: macOS arm64 (M series, 12 CPUs), Docker Desktop 28.4.0, VM with
  8 GiB and kernel `6.10.14-linuxkit`.
- Image: `bench/linux/Dockerfile`, `golang:1.26.1-trixie` (Debian 13) plus
  Debian clang 19.1.7, lld, and the compiler-rt sanitizer runtimes.
- Entry point: `scripts/linux-test.sh [arm64|amd64] [go test args...]`.
  Repo mounted read only; caches and temp files in the Docker volume
  `xo-linux-cache-<arch>`. See toolchain.md, "Linux (containers)".
- linux/amd64 runs under Rosetta (`/proc/cpuinfo`: `VirtualApple`), not
  qemu: that is how this Docker Desktop is configured.

| linux/amd64, Rosetta | `go test -count=1 -p 2 ./...` (full) | 19 of 21 ok; gen and llvm hit the VM's OOM killer | | | |
| linux/amd64, Rosetta | `go test -count=1 -p 1 -parallel 4 ./internal/gen ./internal/llvm` (full) | 2 of 2 ok | 54 / 707 | 0 | 0 |

So every package passes on both. Wall time: arm64 full suite about
6 minutes (internal/gen 354 s, internal/llvm 152 s, internal/arm64 125 s);
amd64 `-short` plus full internal/llvm about 6 minutes; amd64 internal/gen
full 228 s, internal/llvm full 319 s.

What the native runs cover on linux/arm64: 68 goldens of internal/llvm
built with the arm64 backend (ELF, `:lo12:`, `.note.GNU-stack`, ldxr/stxr
count loops) and run with the leak check, the same with share probes, the
bench programs, `testdata/run`, and the layout runs; every LLVM golden
against the Go backend; ThreadSanitizer over `rc_threads.c`, `tasks.c`,
`evloop.c` (epoll, futex, fibers, 8 MiB echo), and the task goldens with
1, 2, and per CPU workers; AddressSanitizer and UBSan over net_echo and
the http_* goldens, the HTTP and JSON differential tests, and the HTTP
fuzz driver; SIGTERM two phase shutdown with both native backends;
the self hosted lexer built with all three backends; `go test -race`
goldens of the Go backend.

On linux/amd64 the LLVM backend targets x86-64: all goldens, the x86_64
fiber switch (`xo_fiber_switch` in top level assembly), epoll, futex, and
signals pass. ThreadSanitizer cannot start under Rosetta, so the TSan
tests run their programs without it there; ASan and UBSan work.

## Failures found and fixes

1. `net_echo` printed `listened on a bad port` with both native backends:
   glibc's getaddrinfo truncates port 99999 to 16 bits instead of failing.
   Fix: `port_out_of_range` in `std/llrt/xo_rt.c` for listen and dial
   (`gotchas/glibc-getaddrinfo-port-truncation.md`). A real bug: a native
   Xo server given a bad port would have listened on another one.
2. UBSan on glibc: `memcpy(p, NULL, 0)` and `qsort(NULL, 0, ...)` (glibc
   declares them nonnull) and `NULL + 0` on lazily allocated buffers in
   `xo_http.c`, `xo_std.c` (`nbuf_put`), and the `http_diff.c` test
   driver. Fixed by guarding zero lengths
   (`gotchas/glibc-nonnull-ubsan.md`). Undefined behavior on every
   platform, reported only on Linux.
3. TSan `memory layout is incompatible` under x86-64 emulation: test
   harness fix, `sanitizerRuns` probe in `internal/llvm/threads_test.go`
   (`gotchas/tsan-under-x86-emulation.md`).
4. `compile: signal: killed` during parallel Go builds: the Docker VM's
   OOM killer, not a code generator bug; the script runs with `-p 2` or
   `-p 1` (`gotchas/docker-vm-memory-go-compile-killed.md`).

Nothing failed in epoll, futex syscalls, the ELF assembly, symbol
prefixes, TLS, the fiber stacks or switch, or signal handling.

## What remains

- ThreadSanitizer on x86-64 Linux needs real x86-64 hardware (a CI
  runner); next step: a GitHub Actions job `ubuntu-latest` running
  `go test ./internal/llvm -run 'Runtime|GoldenTasks|GoldenThreads'`.
  Done on EC2 the same day: `bench/results/ci-aws-2026-10-09.md` (it
  also found a fault unwinding crash under TSan on both architectures).
- No CI runs the Linux suite yet; `scripts/linux-test.sh arm64` is a
  local check. Next step: a workflow with `ubuntu-24.04-arm` and
  `ubuntu-latest` running `go vet ./...` and `go test -p 2 ./...` with
  clang installed.
- The amd64 runs were under Rosetta; qemu (`docker run --platform
  linux/amd64` with the binfmt qemu handler instead of Rosetta) was not
  tried because switching changes Docker Desktop settings.
- Linux musl (Alpine) and older glibc were not tried; next experiment:
  `FROM golang:1.26.1-alpine` with `apk add clang lld compiler-rt` and
  the same script.
