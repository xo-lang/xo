# std/sql memory driver: indexes and writes in place (decision 0528), 2026-11-06

Last verified: 2026-11-06

Decision 0528 gave the memory driver primary key and UNIQUE indexes and made INSERT,
UPDATE and DELETE write the table in place (75093177d). Before it, every write copied the
table, so a write cost O(rows). Host: linux/arm64 offload host 1 (12 CPUs).

Mac sanity (darwin, one run each, not a claim): 100,000 INSERTs took 31.7 s of CPU before
the fix and 0.17 s after; churn at 100,000 rows went from 40.8 s to 0.21 s.

## What it took

Three copies hid the write in place (decision 0528, Implementation): the log form Map keeps
removed values, so a remove then put never left the table unique; CREATE wrote a copy of the
tables map, which turned it into the log form; and closure calls in coerce and compact made
each Db.exec body cancelable, so the Mutex.with body copied the value on its first write
(gotchas/with-body-cancelable-through-closure-call.md).
