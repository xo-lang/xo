# xo test against go test (2026-10-30)

The owner asked (via the lead) how fast `xo test` is against `go test` on
equivalent tests: six std modules whose tests were ported from Go's, each
against the Go package the port came from. Measured on the linux/arm64
offload host (28 CPUs) with Go go1.26.1 and xo at ae79de06c (0.35.0).

## Headline findings

1. **`xo test` parses std in full; `xo build` does not.** The same
   one-test program, after a one-function edit: `xo build` 0.19 s and
   280 MB max RSS, `xo test` 0.27 s and 898 MB. The test build has no std
   variant (the half and the record that `xo build` reads), so its check
   parses 203 files (the build: 109, with 0428's single declarations), the
   heap is 621 MB by `check.prefetch` (the build's: 130 MB), the module
   check cache is off ("cache chk off"), and the heap profile has
   `parser.Parser.parse_file` allocating 629 MB of the 905 MB the build
   allocates. Every xo row below (about 900 MB to 1.2 GB) carries this.
   Next experiment: give `xo test` the std variant and the check cache
   `xo build` uses, then rerun this pair and the table (xo-lang-4's next
   item).
2. **A small package's edit is slower than Go's.** The edit row: base64
   1.52 (411 against 270 ms), url 2.56 (548 against 214 ms); in the large
   packages xo is faster (netip 0.65, json 0.58, regexp 0.16). The edit
   profile of base64 (`--phase-times`): `ssa` 167 ms, of it `fe.build`
   146 ms, `check` 74 ms (`check.dirs` 43, `check.prefetch` 30); every
   cache reports its entries reused (rc 1646/1646, functions 704/704,
   objects 17/17, parts 16/16), so the time is the front end over std's
   sources, not code generation: `--std-module` builds the whole of std
   as source around the module under test. Next experiment: build only
   the module under test from source, the rest from std's store, and
   remeasure the edit row (`--phase-times` of fe.build and check).
3. **Cold, xo is faster but needs 3.4 to 5.3x the memory.** Cold wall 0.34
   to 0.62 of Go's (CPU 0.13 to 0.41), max RSS 1.0 to 1.6 GB against
   Go's 300 MB: finding 1's full parse plus the first build of std's
   caches. Next experiment: after finding 1, the cold row's peak with
   `XO_PROF=heap`.

Also: an unchanged rerun (Go's test cache against xo's run cache) is 0.15
to 0.57 of Go's wall except url (2.61: 130 ms, its run seems not cached;
to check why).

## Rows

- **cold**: every cache emptied before each run (`--guard` removes
  GOCACHE and xo's bin and back-end caches);
- **second**: nothing changed, compile caches warm; Go with `-count=1`
  (reruns from its cached test binary), xo with its run cache directory
  (`$XO_BIN_CACHE/run`) removed before each run, which also drops the
  stored test binary, so xo rebuilds from warm caches and relinks;
- **edit**: one unused function appended before each run to the code
  under test (Go: a copy of GOROOT, `src/PKG/FILE.go`; xo:
  `std/native/MODULE.xo` of the xo under test);
- **rerun**: nothing changed; Go's test cache against xo's run cache.

\* Go's time package tests sleep (timers, tickers, Sleep): about 26 s of
every run is waiting, so its wall rows say nothing about speed; its CPU
column still does.

The test counts differ by design: Go's count is the `=== RUN` lines of
`go test -v` (subtests included), xo's the test blocks, most of them
table driven over Go's cases (netip's 2 blocks cover Go's 327 runs). The
per test figures are therefore not a fair comparison of test code, only
of what one test block costs.

## Commands

On the host, with a private HOME, GOCACHE, GOROOT copy and xo caches
(`XO_BIN_CACHE`, `XO_BACKEND_CACHE_DIR`, `XDG_CACHE_HOME`):

    xo bench --ab --no-guard --keep-loaded --rounds=10 --warmup=1 \
      --args-a="test -count=1 encoding/base64" \
      --args-b="test --std-module=native/base64" \
      [--guard="rm -rf $GOCACHE $XO_BIN_CACHE $XO_BACKEND_CACHE_DIR $XDG_CACHE_HOME"   # cold]
      [--guard="rm -rf $XO_BIN_CACHE/run"                                             # second]
      [--guard="echo 'func l4EditN() int { return 1 }' >> $GOROOT/src/encoding/base64/base64.go;
                echo 'fn l4_edit_N() -> Int { 1 }' >> STD/native/base64.xo"          # edit]
      go xo

(rerun: `--args-a="test encoding/base64"`, no guard). Pairs: base64 /
encoding/base64 (base64.go), url / net/url (url.go), netip / net/netip
(netip.go), json / encoding/json (encode.go), time / time (format.go),
regexp / regexp (regexp.go). The finding 1 comparison: one program with
`use std/base64`, a main and one test; `XO_CACHE_STATS=1 xo build
--phase-times .` and `xo test --phase-times .` after a one-function edit,
under `/usr/bin/time -f %M`; the heap profile with `XO_PROF=heap
XO_PROF_OUT=DIR xo test .` and `xo prof DIR`.
