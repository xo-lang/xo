# arm64 code shape for list heavy integer loops (2026-10-13)

Decision 0208. The arm64 backend's code for List[Int] element access,
32 by 32 to 64 bit products, and list stores in loops, measured on the
Argon2id in Xo that decision 0195 kept in C (2.071x the C's
instructions on arm64, 1.294x on LLVM:
runtime-port-portable-2026-10-13.md), and on bench/perf/text's
`dur_fmt` (decision 0194).

Both emitters (internal/arm64 and selfhost/arm64) change identically:
TestSelfhostArm64 on 64 runs (bench/perf, the SSA goldens,
internal/arm64/testdata, examples) is byte identical, 2,701 functions;
TestSelfhostSSA identical on every stage; TestSelfhostMachoXoTests
passes with the new encodings; internal/arm64 TestGoldenRun, TestRun,
TestLayoutRun, TestFarBranches pass; TestSelfhostWasm 132 pass, 19
unsupported, 0 fail of 151.

## Method

Apple M4 Pro, macOS, instructions retired from `/usr/bin/time -l`, the
minimum of 5 runs (`bench/perf/digest/measure.sh`,
`bench/perf/text/measure.sh`), through the machine wide heavy lock;
other agents were running, so the microsecond columns are noise and
only instruction counts are reported. "less setup" is (workload - none)
of Xo over the same for C, the C path built with `XO_LLRT_C=digest`
(`text` for dur_fmt). Builds use the Go driver (`XO_SELF_DRIVER=0`),
whose emitter output is byte identical to xo1's (the comparison above).
The Argon2id in Xo is the version of commit b54614f2, restored in
commit a4168f52 (with a `zeros` helper and one length check after the
permutation calls, below).

What is left, by measurement:

- **The zero fill of the memory, 23.6 million of the 202.4 million
  arm64 instructions above setup.** `zeros(524288)` 4 times alone
  retires 39,937,473 against 16,369,741 without the calls (a test
  program, scratch build): about 11 instructions a word, a push each
  (capacity compare, store, length store, loop). C uses calloc. Without
  it the arm64 ratio would be about 1.0 ((224.5 - 23.6 - 22.1) / 179.9).
  This needs a zero filled List constructor (decision 0207's raw memory),
  not code shape.
- **LLVM (1.254x)**: none of the arm64 work applies; the SSA reuse hoist
  and the zero fill helper took it from 1.294 to 1.254. clang already
  makes one load per access; the remaining gap is the zero fill and the
  C's vectorized 128 word xor loops.

## The changes (decision 0208)

1. **Element addressing** (isel.go elemAddr, calls.xo elem_addr): a
   constant index is `ldr x, [list, #24 + 8k]`; `xs[i + c]` is `[b, #24
   + 8c]` from the address b of element i (computed once, also for
   `xs[i]` when an `xs[i + c]` exists); another one word element is
   `ldr x, [data, i, lsl #3]` (ldrb with `[data, i]` for Bool) with the
   data address once per block, or once per loop for a list the loop
   cannot move (a data plan beside lsr.go's pointer plans). The memo of
   loaded words knows register offsets.
2. **Lengths across joins**: the block after `a || b` (joinSource) does
   not take the registers of the block that reaches it, so a length it
   loads again had none of the facts of the guard; the facts now follow
   the list (memo lenAt), and a constant index below a known lower bound
   of the length is not checked. blamka_row's 15 bounds checks are gone,
   and so are argon2_g's 768 with the one length check after the
   permutation calls (a `var` List a call returns has an unknown length:
   gotchas/arm64-length-after-var-list-call.md).
3. **Long multiplies**: a product of two values masked to 32 bits (or
   `(x << 32) >> 32`, or known in range, one of them masked or extended)
   is umull (smull); a wrapping add of one used once is umaddl
   (smaddl); a wrapping add of a wrapping shift by a constant is an add
   with a shifted operand. fBlaMka is 3 instructions (was 6). A checked
   unsigned one tests bit 63.
4. **Pairs**: two loads (and now stores, not through sp) of adjacent
   words through one base are paired also across labels nothing refers
   to (the bounds check blocks that are now empty).
5. **Reuse out of loops** (internal/ssa and selfhost/ssa rc): a List
   parameter of a loop header that an update takes directly on every
   iteration, passed back updated or unchanged, is made unique on the
   edges into the loop: the count check, the branch, and the length
   reload leave the loop. `for k in 0..128 { t[k] = a[k] }` is 8
   instructions an iteration (was 15).

The selfhost assembler encodes umull, smull, umaddl, smaddl
(macho_test.xo checks them, and stp with xzr and the register offset
forms, against the system assembler's encodings).
