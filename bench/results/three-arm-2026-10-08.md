# Three arm comparison: plain Go, strict Go, Xo (2026-10-08)

Consolidates the measured results now that Xo programs compile and run
(`internal/gen`). Sources: `go-baseline-2026-10-07.md`,
`planted-and-harder-2026-10-07.md`, `stage2-xo-check-2026-10-07.md`,
`gen-run-v0.4.md`, `planted-xo-2026-10-07.md`.

Notes:
- Xo subjects never saw test results (the compiler could not run code then);
  their tests passed the first time they were executed, so "runs to green"
  for Xo equals runs to a clean check.
- Xo solutions are 45 to 65 percent of the Go line count with a similar
  number of tests (Go counts are top level test functions, some with subtests).
- Strict Go's extra runs were all analyzer findings, 3 of 4 categories false
  positives (nilaway on `http.Client.Do`).

## Bugs

| Measure | Plain Go | Strict Go | Xo |
|---|---|---|---|
| Planted safety bugs caught (30, two Xo authors) | 9 | 13 | 23 to 29 (25 to 29 with warnings) |
| Planted logic bugs caught by tests (20) | 17 | 17 | 16 |
| Unplanted real bugs found in subject code | 0 by tools (1 goroutine leak by design review) | 1 latent nil | 1 overflow found by contract fuzzing |

## Reading

1. For writing code that passes its own tests, Go and Xo are even: both pass
   on the first try almost always. Go needs no spec in context; Xo needs
   about 30k tokens of spec per session.
2. Xo's advantage is in bugs tests do not catch: 23 or more of 30 planted
   safety bugs against 13 for strict Go, with logic bug detection equal. The
   remaining Xo escapes are mostly explicit, reviewable choices
   (`ignore_err`, `_` on prelude enums).
3. Xo code is about half the size for the same behavior and test count.
4. Contract fuzzing found a real bug that no other arm's tooling would have.

## Limits

- Five tasks for planted bugs; eight for writing. Small samples.
- Planted bugs were authored by agents; author choice moves the Xo number by
  up to 6 of 30 (two authors measured).
- The stage 2 Xo subjects used a frozen checker (`xo-0.4`); later spec rules
  (0.5, 0.6) would flag one error and one warning in their code today.
- Performance is not compared yet (`Map.put` is about 45x slower than a Go map).
