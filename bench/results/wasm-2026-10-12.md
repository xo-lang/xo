# The WebAssembly backend in Xo, stage 1 (decision 0179), 2026-10-12

Machine: the shared 12 core Mac (darwin/arm64, 24 GB), about ten agents
running at once, so wall clock times are noisy (load average 6 to 11);
counts and sizes are exact. Node 22.22.1 runs the modules
(`selfhost/wasm/run.mjs`: WASI preview1 in a worker, single threaded
GC).

## Goldens

`go test ./internal/selfhost -run 'TestSelfhostWasm$'` (selfhost/wasm
built with the go backend; every golden of internal/llvm/testdata/golden
lowered, run under Node, compared with want.txt, and run again with
XO_LEAKCHECK=1): **71 pass, 62 unsupported, 0 fail of 133**, 29 s.

A golden passes when its exit status, standard output, and fault lines
equal want.txt and every allocation is freed. An unsupported one fails
the build with `the wasm backend does not support ...` and no module; no
golden ran with wrong output. The unsupported ones, by the first

## The self hosted driver

`xo1` (selfhost/xo built with `--backend=arm64`, 315 s on the loaded
machine) runs `xo1 build --backend=wasm -o recursion.wasm` on the
golden `recursion` in 1 s; the module (16,659 bytes, WAT text 122,561
bytes) is byte identical to the one the go build of selfhost/wasm
writes, and prints want.txt's output under Node. (The go backend build
of selfhost/xo fails on main itself, "selfhost_lexer imported and not
used"; not this change.)

## Sizes

Every module the goldens produced (71): **min 12,230 bytes, median
16,149, max 129,329** (byref_struct: structs of 256 bytes and more are
many leaves). The runtime (rt.xo assembled with every program) is most
of the smallest module. A native arm64 build of the same goldens is
about 381,500 bytes (recursion 381,736; it links the C runtime).

## Run time

Wall clock, best of 5, including Node's start (an empty module: 70 to
72 ms). The goldens are too short to compare (recursion 91 ms vs 12 ms
native, loops 74 vs 2, rc_recursive 160 vs 28; arith, sort_structs,
lists, strings, generics 74 to 77 ms vs 2 to 3 ms: Node's start). Three
CPU programs (scratch, not committed; same output on both):

| program | wasm (after Node's start) | native arm64 | ratio |
|---|---|---|---|
| fib(32), recursive calls | 106 ms (36 ms) | 8 ms | 4.6x |
| sieve of 2,000,000 ten times, List[Bool] | 531 ms (461 ms) | 43 ms | 10.6x |
| 300,000 structs with Str fields, 100,000 appends to a Str | 96 ms (26 ms) | 10 ms | 2.8x |

The sieve shows the costs of stage 1's lowering: every block is
entered through the dispatch loop's `br_table`, and a checked index is
a call into the runtime; stage 3 (structured control flow, inline
checks) addresses both.

## Code

selfhost/wasm: asm.xo 1,164 lines (the WAT assembler), gen.xo 1,016
(module state, value leaves, helpers), func.xo 648 (functions), call.xo
365 (calls), rt.xo 5,141 (the runtime in WAT), main.xo 163, run.mjs 63;
selfhost/xo/wasm.xo 25 lines.

## What stage 1 did not cover, next

Stage 2: the std runtime the single threaded goldens call (strconv
quoting and case mapping from Unicode tables generated into Xo, time
and clock through WASI clock_time_get, random through random_get,
base64, JSON text). Stage 3: structured control flow and inline
checks, output buffering. Stage 4: selfhost/xo built by this backend
(file system through WASI), then the playground of decision 0144
without the Go toolchain. Stage 5: tasks on one thread.

# Stage 2 (decision 0179, stage 2 section), 2026-10-12

Same machine and load; counts from `selfhost/wasm --each` over every

each module run under Node as `TestSelfhostWasm` runs it (want.txt,
then the leak check). The stage 1 build measured on main after the

## Step 1: Unicode and strings

The Unicode operations (case mapping, quoting, the Rune classes, the
lower compare) are std/native/llrt/unicode.xo and its generated tables,
compiled by this backend like the program; the backend adds the
primitives they and the native prelude call (`selfhost/wasm/rt2.xo`):
`str_byte`, `bytes_span`, `rs_append_bytes`, `rs_append`,
`rune_is_space`, `utf8_valid`, `bytes_decode`, `bytes_rune_count`,
`int_parse_ok`, `int_parse`, `str_of_byte`, `str_replace`,
`b64_encode`, `b64_ok`, `b64_decode`, `duration_parse_ok`,
`duration_parse`.

**85 pass, 49 unsupported, 0 fail of 134** (14 more: cli_completion,
cli_decl_fault, cli_fault, cli_parse, cli_usage_exit, csv_basic,
method_values, native_eq_lower, native_prelude, native_sized_ints,
native_values_hof, regexp_table, std_error_display, unicode_table).

## Step 2: tasks without threads

Function tables for the task entry points and list drops (`funcaddr`),
handles (one i32: a runtime object `{rc, free function, ...}`), and the
task runtime `selfhost/wasm/rt3.xo`: scopes, spawn, await, channels,
select, Mutex, Atomic, cancellation, shields, timers (`clock.sleep`,
`select ... after`, `task.with_timeout` through WASI `clock_time_get`
and `poll_oneoff`), and budgets (`rt.tick`), on one thread under a
cooperative scheduler. A task that waits suspends by unwinding its wasm
stack into a save area of its own and is resumed by rewinding it
(Asyncify's technique, generated by the backend: only functions that can
reach a wait are instrumented). Also `rand` through WASI `random_get`,
`Time.unix` (`floor_div`), `int_wrap`/`int_fits`, `crypto_b64`, and
real-time sections (XO-F007).

**113 pass, 21 unsupported, 0 fail of 134** (28 more than step 1). The
same 20 task goldens (conc_*, fault_tasks, fault_task_exit,
select_arm_order, clock_timers, map_until, task_native, task_budget)
passed three runs in a row: the scheduler runs tasks in spawn order, so
the output is the same every run.

What is still unsupported, by the first construct (21):

| first construct not supported | goldens |
|---|---|
| the network (`rt.net_listen`: WASI preview1 has no sockets) | 8 |
| `rt.rs_append_json_str`, `rt.rs_append_time` | 2 each |
| `rt.fs_mkdir_all` (files) | 2 |
| `rt.time_of`, `rt.const_once`, `rt.crypto_sha256`, `rt.proc_exec`, `rt.canonical_key`, `rt.isatty`, `rt.json_parse` | 1 each |

Instrumentation: functions that can suspend, of the program's
functions (WAT `block $S`): conc_channels 7 of 15, conc_stress 9 of 18,
conc_scopes 15 of 36, task_native 25 of 55.

Sizes of the 113 modules: min 16,631 bytes, median 24,492, max 373,479
(regexp_table: the Unicode range tables as Bytes literals); recursion
20,583 (16,659 at stage 1: the stage 2 runtime functions are assembled
into every module, used or not; dropping the unused ones is next).
A task program carries the task runtime too: conc_channels 57,618
bytes, conc_stress 42,740.

Run time (wall clock, best of three, Node's start of about 70 ms
included; noisy machine): conc_channels 0.17 s (a thousand values
through an unbuffered channel and a worker pool), conc_stress 0.10 s.

## Step 4: toward the playground (the self hosted compiler as wasm)

What the self hosted front end needs beyond the goldens' runtime is
`selfhost/wasm/rt4.xo`: reading the file system through WASI preview1
(`path_open`, `fd_read`, `path_filestat_get`, `fd_readdir`; run.mjs
preopens the working directory as fd 3 and `/` as fd 4), the constants
of collection types (`const_once`), Time as Unix nanoseconds, and
SHA-256 (checked against Python's hashlib on three inputs). With it
native_bytes passes too: the 114 above. `selfhost/wasm --why` lists every
unsupported construct of a program, `--lax` turns an unsupported runtime
call into a fault where it runs (to see how far a program gets; never
for a shipped module).

| component (Xo lines) | module | build (go backend selfhost/wasm) | run under Node vs the go backend build |
|---|---|---|---|
| selfhost/lexer (1,873) | 199,696 bytes | 0.27 s, 101 MB | 5 files, 40,578 tokens: identical output, 0.39 s vs 0.04 s |
| selfhost/parser (7,946) | 5,990,762 bytes (WAT 38 MB, 2,018,620 lines) | 2.0 s, 597 MB (1.21 GB before the two fixes below) | 3 files, 27,687 lines of AST dump: identical output, 7.3 s vs 0.15 s |

The lexer and the parser of the self hosted compiler run as wasm and
print exactly what their go backend builds print.

Memory of the build is the first obstacle. The first build of
selfhost/check thrashed on the loaded machine (swap 57 GB of 58 GB in
use) and was stopped after 10 minutes; so was a second one after 45
minutes with 4 minutes of CPU. Two fixes: the assembler keeps a token
as three Ints (kind and source offsets) instead of a Str and a list
(assembling parser.wat alone: 988 MB to 578 MB, byte identical output),
and the functions' text is dropped before assembling, with the token
list sized from the text (the parser build: 597 MB to 381 MB).

Every module also carried all of the runtime; now only the runtime
functions the program reaches are assembled (the calls of its code, the
function table, the exports). Sizes of the 114 modules: **min 2,907
bytes, median 11,575, max 358,795** (regexp_table); recursion 7,481
(20,583 before, 16,659 at stage 1), conc_channels 41,067, conc_stress
26,999.
