# The WebAssembly backend in Xo, stage 1 (decision 0179), 2026-10-12

Machine: the shared 12 core Mac (darwin/arm64, 24 GB), about ten agents
running at once, so wall clock times are noisy (load average 6 to 11);
counts and sizes are exact. Node 22.22.1 runs the modules
(`selfhost/wasm/run.mjs`: WASI preview1 in a worker, single threaded
GC).

## Goldens

`go test ./internal/selfhost -run 'TestSelfhostWasm$'` (selfhost/wasm
built with the go backend; every golden of internal/llvm/testdata/golden
lowered, run under Node, compared with want.txt, and run again with
XO_LEAKCHECK=1): **71 pass, 62 unsupported, 0 fail of 133**, 29 s.

A golden passes when its exit status, standard output, and fault lines
equal want.txt and every allocation is freed. An unsupported one fails
the build with `the wasm backend does not support ...` and no module; no
golden ran with wrong output. The unsupported ones, by the first
construct the backend stops at:

| first construct not supported | goldens |

| `rt.net_listen` (network) | 7 |
| `rt.scope_open` (scopes) | 4 |
| `rt.rand_int` | 4 |
| handle types (TLS certificate, `native.rt.Any`, Mutex) | 4 |
| `rt.tick` (task budgets), `rt.str_lower`, `rt.atomic_new` | 2 each |
| `rt.utf8_valid`, `rt.str_eq_lower`, `rt.rune_quote`, `rt.rs_append_time`, `rt.rs_append_json_str`, `rt.realtime_enter`, `rt.isatty`, `rt.duration_parse_ok`, `rt.clock_now`, `rt.b64_encode` | 1 each |

(From the test's `unsupported` lines: each golden under the first
construct the backend stopped at; 62 in all.)

## The self hosted driver

`xo1` (selfhost/xo built with `--backend=arm64`, 315 s on the loaded
machine) runs `xo1 build --backend=wasm -o recursion.wasm` on the
golden `recursion` in 1 s; the module (16,659 bytes, WAT text 122,561
bytes) is byte identical to the one the go build of selfhost/wasm
writes, and prints want.txt's output under Node. (The go backend build
of selfhost/xo fails on main itself, "selfhost_lexer imported and not
used"; not this change.)

## Sizes

Every module the goldens produced (71): **min 12,230 bytes, median
16,149, max 129,329** (byref_struct: structs of 256 bytes and more are
many leaves). The runtime (rt.xo assembled with every program) is most
of the smallest module. A native arm64 build of the same goldens is
about 381,500 bytes (recursion 381,736; it links the C runtime).

## Run time

Wall clock, best of 5, including Node's start (an empty module: 70 to
72 ms). The goldens are too short to compare (recursion 91 ms vs 12 ms
native, loops 74 vs 2, rc_recursive 160 vs 28; arith, sort_structs,
lists, strings, generics 74 to 77 ms vs 2 to 3 ms: Node's start). Three
CPU programs (scratch, not committed; same output on both):

| program | wasm (after Node's start) | native arm64 | ratio |
|---|---|---|---|
| fib(32), recursive calls | 106 ms (36 ms) | 8 ms | 4.6x |
| sieve of 2,000,000 ten times, List[Bool] | 531 ms (461 ms) | 43 ms | 10.6x |
| 300,000 structs with Str fields, 100,000 appends to a Str | 96 ms (26 ms) | 10 ms | 2.8x |

The sieve shows the costs of stage 1's lowering: every block is
entered through the dispatch loop's `br_table`, and a checked index is
a call into the runtime; stage 3 (structured control flow, inline
checks) addresses both.

## Code

selfhost/wasm: asm.xo 1,164 lines (the WAT assembler), gen.xo 1,016
(module state, value leaves, helpers), func.xo 648 (functions), call.xo
365 (calls), rt.xo 5,141 (the runtime in WAT), main.xo 163, run.mjs 63;
selfhost/xo/wasm.xo 25 lines.

## What stage 1 did not cover, next

Stage 2: the std runtime the single threaded goldens call (strconv
quoting and case mapping from Unicode tables generated into Xo, time
and clock through WASI clock_time_get, random through random_get,
base64, JSON text). Stage 3: structured control flow and inline
checks, output buffering. Stage 4: selfhost/xo built by this backend
(file system through WASI), then the playground of decision 0144
without the Go toolchain. Stage 5: tasks on one thread.

## Step 1: Unicode and strings

The Unicode operations (case mapping, quoting, the Rune classes, the
lower compare) are std/native/llrt/unicode.xo and its generated tables,
compiled by this backend like the program; the backend adds the
primitives they and the native prelude call (`selfhost/wasm/rt2.xo`):
`str_byte`, `bytes_span`, `rs_append_bytes`, `rs_append`,
`rune_is_space`, `utf8_valid`, `bytes_decode`, `bytes_rune_count`,
`int_parse_ok`, `int_parse`, `str_of_byte`, `str_replace`,
`b64_encode`, `b64_ok`, `b64_decode`, `duration_parse_ok`,
`duration_parse`.

**85 pass, 49 unsupported, 0 fail of 134** (14 more: cli_completion,
cli_decl_fault, cli_fault, cli_parse, cli_usage_exit, csv_basic,
method_values, native_eq_lower, native_prelude, native_sized_ints,
native_values_hof, regexp_table, std_error_display, unicode_table).
