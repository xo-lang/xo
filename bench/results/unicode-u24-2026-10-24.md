# The Unicode tables read little endian: one load per table value, 2026-10-24

Follow-up to `case-mixed-2026-10-24.md`, item 4 of the list there. The
profile of the mixed case rows put `unicode.u24` at 34 percent of
`lower_u` and 19 percent of `upper_u`: three bounds checked index reads
and two shifts per table value, where the table entry is three bytes.
`u24` also reads the class range tables, so every `Rune.is_*` pays it.

## The change

- The tables of `std/native/llrt/unicode_tables.xo` are now 24 bit
  little endian values followed by eight zero bytes of pad, instead of
  big endian with no pad (`internal/llvm/unicode_test.go`, TestUnicodeTables;
  the file is regenerated, not edited).
- `unicode.u24` is one `rt.bytes_word` and a mask:
  `rt.bytes_word(t, i) & 0xffffff`. The pad makes the eight byte load safe
  for the last entry, which starts three bytes before the table's end.
- `regexp.xo` keeps its own big endian `u24` for `unicode_classes.xo`,
  which is a different generated file and is not changed here.

## What it is worth

`bench/perf/unicode`, Xo arm64, base worktree at `origin/main` and the
branch built by an xo of the same revision, both programs from the same
`main.xo`, `xo bench --ab --rounds=9 --keep-loaded`, instructions,
ratio B / A:

| workload | base | now | B / A |
|---|---|---|---|
| lower_u (mixed to_lower) | 4,211,048,540 | 3,555,118,613 | 0.844 (0.844 to 0.845) |
| upper_u (mixed to_upper) | 4,169,188,472 | 3,513,285,797 | 0.843 (0.842 to 0.845) |
| runecase (Rune.to_lower/to_upper) | 200,836,709 | 152,487,671 | 0.759 (0.757 to 0.768) |
| eqlower (case insensitive compare) | 10,836,094,078 | 9,516,932,247 | 0.878 (0.878 to 0.879) |
| lower (ASCII) | 378,803,599 | 380,002,919 | 1.003 (0.996 to 1.007), within noise |
| upper (ASCII) | 387,801,250 | 387,779,290 | 1.000 (0.998 to 1.005), within noise |

The ASCII rows do not touch the tables, as expected.

## Correctness

- `TestUnicodeTables` (the generator's sync test) passes in both modes.
- Corpora `runes`, `strings`, `trimchars`, `equalfold` and `strwhere` on
  arm64, LLVM and the Go backend.
- Goldens `unicode_table` and `native_eq_lower` on arm64 and LLVM, and
  the Go backend against the same `want.txt`.
