# Optional pass miscompile hunt, 2026-11-02

Owner direction (2026-11-02): no new micro size or speed passes; hunt
miscompiles in the optional passes that exist. Each search builds programs
on the native backend with one optional pass off (`XO_PASSES=-PASS`), or
all of them off, and compares the output with the LLVM backend's
(`want.txt`). A difference, a build failure or a crash names the pass.
Xo Lang 1, all runs on 2026-11-02.

## Miscompiles found and fixed

- slp_f64 (compiler/arm64 slp.xo) sank a pair of Float stores past a load
  through another reference to the same list: 4f3a667a4 (golden
  slp_alias_store, gotcha store-sunk-past-aliasing-load). It shipped in
  v0.25.0 through v0.35.0 (introduced in eff7996a8).
- slp_f64 extracted the lanes of a build in the wrong order when the build
  read them swapped (found by Lang 3's progen Alias seed 387): f58b4116f
  (goldens slp_alias_387, slp_build_swapped).

## Hunt (2): large goldens, each pass off

`hunt2-host.sh` on main 65444e344: the 40 largest goldens by source, each
built natively with each of the 56 optional passes off in turn and with
all of them off (57 builds each). A build

(558 of 2280); the other 1722 ran against want.txt. No differences and no

## cancel_rc_pairs and sink_retains survey

On main 211ee8df7, every golden (520) built with the default passes and
with each pass off; a golden whose .text changes ran both ways against
want.txt.

- cancel_rc_pairs changes code in exactly 80 goldens (http, tls,
  websocket, net, time zones, templates, url, multipart, sql: mostly
  through std) and in compiler/xo itself. All 80 pass on and off. It is
  live, not dead code.
- sink_retains changes all 520. With it on, 520 pass; off, 519 passed and
  http_trailers failed once. The failure did not repeat in 12 sequential
  runs or 60 runs 12 at a time, which led to the stress below.

## http_trailers under load

http_trailers, 15 rounds of 64 copies beside 18 CPU burners, with the
default passes and with sink_retains off: 960 runs each. One run with the
default passes timed out ("h2 up: request timed out"); the passes were
not the cause. Lang 4 found the h2 server's trailing HEADERS path ended
the stream without waking its handler and fixed it in a144a3115, with a
deterministic TestH2Diff case.

## Concurrency goldens under load

110 goldens whose names match http, h2, websocket, tls, chan, select,
sched, thread, timer, net or proxy (a fixed port golden runs once per
round), 4 rounds of 64 copies, burners on every CPU, on main ebb8b4fbb:
27,920 runs on each host. No crashes, hangs or nonzero exits. The wrong
outputs:

- net_lookup_dial_timeout, 3 runs on linux/arm64 and 1 on linux/amd64: a
  dial to an unroutable address reported a connection (netconn
  connect_wait took a wake with SO_ERROR 0 as connected; Go confirms
  with getpeername).
- tls_deadline, 6 runs on linux/arm64: a write after a deadline in the
  past succeeded (a past deadline was stored as `now | 1`, one ns ahead
  of an even clock reading).
- http_pipe, 1 run on linux/arm64: two fibers' lines printed in the
  other order, a race in the test itself.

The three fixes are 0.36 work, each with a std change log entry and a
test that fails before it.
