# Windows on the LLVM backend, stage 1 (2026-10-12)

Decision 0197 (stage 1 of the Windows gate of decision 0196).

## Host

EC2 i-EXAMPLE19, c7i.4xlarge (16 vCPU, 32 GiB), on demand,
us-east-1, Windows Server 2025 Datacenter (ami-EXAMPLE01,
Windows_Server-2025-English-Full-Base-2026.09.17), set up by
scripts/remote-windows.sh: LLVM 23.1.3 (clang, lld-link; target
x86_64-pc-windows-msvc), VS 2022 Build Tools (MSVC and the Windows SDK),
Go 1.26.1, Git for Windows (latest on 2026-10-12). Setup took about 11
minutes.

## Milestone: hello world

`XO_SELF_DRIVER=0 xo.exe build --backend=llvm -o hello.exe hello`
(`fn main(os: Os) { os.stdio.println("hello, windows") }`) built a
169,472 byte PE executable in 2.6 s (first build, runtime compiled
locally) that prints `hello, windows\n` (LF, binary mode) and exits 0.

## Golden suite

`XO_GOLDEN_WANT=1 go test -count=1 -run TestGoldenWant -v ./internal/llvm`
on the instance: every program of internal/llvm/testdata/golden built
with the LLVM backend alone, its run compared with want_windows.txt when
present, else want.txt, plus the leak check (XO_LEAKCHECK=1, 0 live) for
programs that exit 0. Unsupported means the build stopped with XO1504.

|---|---|---|---|---|
| runtime builds (threads, fibers, faults, timers); checkout with CRLF | 0 | 127 | 16 | 143 |
| same, checkout with LF (gotchas/windows-git-crlf-goldens.md) | 126 | 1 | 16 | 143 |
| want_windows.txt for method_values (prints `target windows`) | 127 | 0 | 16 | 143 |
| Fs operations (xo_fs.c on Win32) | 129 | 3 | 11 | 143 |
| Fs error classes, sockets (WSAPoll), HTTP, TLS, standard input | 139 | 1 | 3 | 143 |

| after merging main (144 goldens: one added there) | 140 | 1 | 3 | 144 |

Final run: **140 pass, 1 fail, 3 unsupported, of 144** (summary line of
TestGoldenWant, windows/amd64).

- Fail: env_program. The program joins `$PWD` and the program path when
  the path has no `/`; on Windows the path is `C:\...`, so the joined
  path names no file (`names a file: false`). The Go backend on Windows
  fails the same program harder (`Io(path: "C:\\...\\internal\\llvm/C:\\...",
  msg: "The filename, directory name, or volume label syntax is
  incorrect.")`): Windows absolute paths in std are stage 4.
- Unsupported (XO1504, processes): proc_cmd, net_only, unix_kill.
- Target dependent want files: method_values (`target windows true`),
  fs_files (permission bits: Windows keeps only read-only, so 0o750 and
  0o600 read back as 0o666 = 438, as Go's os on Windows reports).
- The Go backend on the same host (TestGolden's Go side, 2026-10-12)
  differs from want.txt in fs_native too (`missing NotDir(...)` for a
  missing parent, `read dir Io(..., msg: "Incorrect function.")`); the
  LLVM backend follows want.txt's (POSIX) error classes there.

Wall time of the golden run on the instance: 28 s (16 vCPU, warm
caches; one agent on the host).

## windows/arm64: cross builds (not run)

`xo build --backend=llvm --targets=windows/arm64` on the windows/amd64
instance (clang `--target=aarch64-pc-windows-msvc`, the VS ARM64 tools
and the SDK's arm64 libraries) builds hello world into a PE32+ ARM64
executable (`file`: "PE32+ executable for MS Windows 6.00 (console),
ARM64, 7 sections").

`XO_GOLDEN_WANT=1 XO_GOLDEN_WANT_TARGET=windows/arm64 go test -run
TestGoldenWant ./internal/llvm`: **141 built, 0 fail, 3 unsupported, of
144** (the 3 are processes, XO1504). The first run had 135 built and the
6 HTTP programs failing in the TLS library (sha512.c's Windows on Arm
branch leaves its CPU detection function undeclared; the Xo
configuration no longer asks for it there). None of them has run: EC2
offers no Windows arm64 image (describe-images with platform windows,
architecture arm64: 0 on 2026-10-12), so running them needs another host
(decision 0197, stage 3).

## Stage 2: processes, and xo1 builds Windows (2026-10-12, second agent)

Host: EC2 i-EXAMPLE22 (c7i.4xlarge, Windows Server 2025, the
same image and setup as above), held by `scripts/remote-windows.sh
--hold`.

xo_proc.c runs commands with CreateProcessW (decision 0197 stage 2):
the command line quoted as Go's syscall.EscapeArg (and on any space
character, for MSYS2 programs), the three standard handles passed in a
PROC_THREAD_ATTRIBUTE_HANDLE_LIST, pipes the program reads or writes
pumped by a thread to a loopback socket the poller waits on, a killed
child ending with status 137. XO1504 no longer names any part.

Go driver, `XO_GOLDEN_WANT=1 go test -run TestGoldenWant ./internal/llvm`:

| Step | Pass | Fail | Unsupported | Of |
|---|---|---|---|---|
| stage 1 (above) | 140 | 1 | 3 | 144 |
| processes ported (proc_cmd, net_only, unix_kill run) | 143 | 1 | 0 | 144 |

The fail is env_program (Windows paths, stage 4). Target dependent want
files added: proc_cmd/want_windows.txt (Git for Windows' sh reports a
child killed by signal 9 as exit code 2304, 9 << 8, and sets HOME
itself when the environment lacks it) and unix_kill/want_windows.txt
(only KILL is sent on Windows; the program now kills the child itself
when TERM or QUIT is refused, which changes nothing where they are
sent).

xo1 (the shipped xo, built on the instance from selfhost/xo by the Go
seed with the Go backend, `XO_SELF_DRIVER=0 xo build -o xo1.exe
./selfhost/xo`, 48 s) with the Windows driver port (host, user cache
directory, PATH and PATHEXT lookup, NUL, lld link, the TLS library's
xo/win and Curve25519 defines, bsdtar, drive paths in the checker and
the driver, and llvm_cross_triple):

`XO_GOLDEN_WANT=1 XO_GOLDEN_WANT_XO=C:/Users/Administrator/xo1.exe go
test -run TestGoldenWant ./internal/llvm` (each golden built by `xo1
build --backend=llvm`):
