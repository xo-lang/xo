## Stage 5: fidelity (2026-10-12)

Same host (i-EXAMPLE22). Timings are wall clock on a 16 vCPU
instance with this agent alone on it; one run each.

### Socket readiness: AFD polls on a completion port

The poller waits on an I/O completion port; a task that waits for a
socket arms a one shot IOCTL_AFD_POLL on `\Device\Afd` for the
directions waited in, and the completion hands the readiness over
(XO_WINPOLL=wsapoll keeps the stage 1 WSAPoll loop, also the fallback
when the device does not open). bench/perf/winpoll: one loopback
connection's 1 byte round trip, 20,000 rounds, while IDLE other
connections each have a task blocked reading them
(`XO_IDLE=N XO_ROUNDS=20000 winpoll.exe`, LLVM backend):

| Idle connections | AFD round trip | WSAPoll round trip |
|---|---|---|
| 0 | 44.5 us | 27.8 us |
| 1000 | 43.9 us | 994.0 us |
| 4000 | 44.0 us | 11935.4 us |

AFD stays flat; WSAPoll rebuilds and scans an array of every waited
socket on each wait. With nothing idle AFD costs about 17 us more per
round trip (an arm and a completion per wait against one WSAPoll call).
Goldens with xo1 building: 145 of 145 pass with AFD (three runs) and
145 of 145 with XO_WINPOLL=wsapoll. One golden (http_tls) failed with
AFD until the HTTP/2 connection wait (xo_h2.c h2_wait, which sets its
read waiter itself) armed the poll too.

### Standard input: a reader thread

A pipe or console standard input is read by a thread of its own into a
loopback socket the poller waits on (xo_w_pump, shared with the process
pipes), so reads are cancellation points as on Unix; a file is read
directly. A program reading a line under `task.with_timeout(clock, 1s,
...)` with a pipe that sends its line after 2 s (`(sleep 2; echo late)
| prog`), LLVM backend on the instance: `first read: TimedOut`, `after
1000 ms`, then `second read: late`; the same program with a file prints
the file's line at once (stage 1's blocking read would have returned the
line after 2 s instead of timing out).

### The local time zone from the system setting

"Local" on Windows is built from GetDynamicTimeZoneInformation (the
registry's TimeZoneInformation), as Go's time.Local: the standard offset,
and the daylight saving dates as a POSIX TZ rule; abbreviations from Go's
CLDR derived table by the zone's key name (139 zones), else the
capitals of its name. Stage 1 gave UTC. `time.local(os.env)` at
2026-01-15 12:00 UTC and 2026-07-15 12:00 UTC under eight system zones
set with tzutil (the instance's zone restored after):

| System zone | LLVM backend | Go backend |
|---|---|---|
| UTC | +0 UTC, +0 UTC | same |
| Pacific Standard Time | -8 PST, -7 PDT | same |
| W. Europe Standard Time | +1 CET, +2 CEST | same |
| India Standard Time | +5.5 IST, +5.5 IST | same |
| AUS Eastern Standard Time | +11 AEDT, +10 AEST | same |
| Nepal Standard Time | +5.75 +0545 (both) | same |
| Morocco Standard Time | +0 +00, +1 +01 | same |
| Pacific SA Standard Time | -3 -03, -4 -04 | same |

The zone's name stays "Local" on both backends (an IANA name would need
the CLDR table on the Go backend too).

### The environment in UTF-8

The runtime reads a UTF-8 copy of GetEnvironmentStringsW (names
without case) instead of the C runtime's ANSI `_environ` and `getenv`.
`XO_UTF8="héllo ✓ 日本"` read by `env.get`, `env.vars`, a differently
cased name, and a child (`sh -c 'printf %s "$XO_UTF8"'`), plus a
`set_env` value: before, `get h�llo ? ?? bytes 10` (the ANSI code page
lost every character outside it; the child still saw the right value);
now `get héllo ✓ 日本 bytes 17` for all three reads, as the Go backend
prints.

### Stack overflow

A vectored exception handler reports EXCEPTION_STACK_OVERFLOW as the Go
backend does (still not a fault, decision 0085): the buffered output,
`fatal error: stack overflow` on standard error, status 2; every thread
keeps 64 KiB past its guard page for it (SetThreadStackGuarantee).
Unbounded recursion on main's stack and in a task (a fiber stack):

| Build | Where | Before | Now |
|---|---|---|---|
| LLVM | main | killed by the system (Git Bash reports status 139, a segmentation fault), no output at all (the buffered `start` lost) | `start`, `fatal error: stack overflow`, status 2 |
| LLVM | task | same | same as main |
| Go backend | main and task | `start`, `fatal error: stack overflow` and frames, status 2 | unchanged |

A first handler without the stack guarantee was never seen to run (the
process still died with 139): the overflowed stack had no room left
for exception dispatch.

Goldens with xo1 building, after the reader thread, the zone, the UTF-8
environment, and this handler: 145 of 145 pass.

### Sockets apart from C runtime descriptors

Sockets are their SOCKET handle's value and C runtime descriptors above
2 now carry a tag bit (0x40000000) that the shims take off, so the two
never share a number; before, `close` tried `closesocket` first and a
file's descriptor could equal a live socket's handle. A program with 8
echoed loopback connections that opens and closes N files, then pings
each connection:

| Files | Before (connections still working) | Now |
|---|---|---|
| 100 | 8 of 8 | 8 of 8 |
| 520 | 8 of 8 | (not rerun) |
| 560 | 7 of 8 | (not rerun) |
| 600 | 5 of 8 (`write tcp: not a socket`) | (not rerun) |
| 1000 | 0 of 8, and removing the directory failed with Denied (files left open) | 8 of 8 |
| 3000 | 0 of 8 | 8 of 8 |

The handles of that run's sockets were 572 to 676: from about 550 open
files the descriptor numbers reached them. A set of open sockets
consulted by `close` (tried first) did not help: the same number was a
live socket and a live descriptor. Goldens with xo1 building: 145 of
145 pass.
