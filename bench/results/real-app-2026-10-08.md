# Real application: notes-service (2026-10-08)

One realistic service written in Xo against spec 0.7 / std draft 0.6 to find
gaps that the benchmark tasks do not reach: `examples/notes-service/`.

What it does: HTTP JSON API (`GET /health`, `POST/GET /notes`,
`GET/DELETE /notes/{id:Int}`), users and notes in `std/sql` (in memory
driver), bearer token middleware checked against a `users` table, a
background purge job (`spawn_background` + `clock.sleep`), two phase shutdown
through `serve`, and 9 tests (handlers via `Router.call`, auth failures, header
spoofing, ownership, bad input, `purge_expired`, the purge loop on virtual
time, and an end to end `testing.run_main` with `signal_after`).

## Result

| Step | Outcome |
|---|---|
| `xo check` | 2 errors on the first try (`Float.from`, missing `uses` on a `pub fn`), both fixed in one edit |
| `xo test` | 9/9 passed on the first run; also with `--explore=20` |
| `xo build --targets=all` | 7 targets built (darwin, linux, windows on amd64/arm64, wasip1) |
| `xo fmt --check`, `xo vet` | clean |
| Real run (darwin/arm64) | POST 201, unauthenticated 401, list ok; SIGTERM exits 0 after logging `stopped` |

No compiler or std change was needed. About 210 lines of service and 150 of
tests.

## Gaps, ranked by impact

Status (2026-10-08, later the same day): gaps 1 to 5 are resolved and gap 7
is half resolved; see "Follow up" at the end. Each entry below keeps its
original text, with a status line.

1. **No request scoped values: middleware cannot pass the authenticated user
   to handlers.** `http.Request` has only `headers`, `body`, and friends.
   Workaround: the middleware writes the user id into an `X-Notes-User`
   header (`req with {headers: ...}`) and handlers parse it back. This is
   stringly typed and a security trap: it is only safe because the
   middleware overwrites any client supplied value and every route sits
   behind it (see gotcha `middleware-identity-header-spoofing.md`).
   Proposed fix: typed request locals in std/http,
   `pub fn key[T](name: Str) -> Key[T]`, `fn (r: Request) with_value[T](k: Key[T], v: T) -> Request`,
   `fn (r: Request) value[T](k: Key[T]) -> T?`, carried by `Router.call` and
   `serve`, invisible to the network.
   **Resolved 2026-10-08** (decision 0055): `http.Key[T]`, `http.key[T](name)`,
   `req.with_value(k, v)`, `req.value(k) -> T?`; keys are identified by name
   and type, so no global is needed.

2. **Middleware is router global and cannot fail.** `wrap` applies to every
   route, so the public `/health` route is exempted by comparing
   `req.path` inside the middleware, and the middleware builds its own 401/500
   JSON bodies, duplicating the `StatusError` mapping that handlers get for
   free. Proposed fix: (a) `fn ([var] r: Router) group(prefix: Str) -> Router`
   or `r.handle_with(mw, pattern, h)` so middleware can be scoped; (b) accept
   `fn(Request, Next) -> Response ! E` in `wrap` and apply the section 4.2
   mapping to `Err(e)`.
   **Resolved 2026-10-08** (decision 0055): `wrap` takes
   `fn(Request, Next) -> Response ! E` with the 4.2 mapping, and
   `r.mount(prefix, sub)` scopes `sub`'s middleware to its routes (one
   route: mount a one route router).

3. **`Listener` has no methods, so `listen(":0")` cannot report its port.**
   The end to end test must pick a fixed address and hand it to `main`
   through `os.env`, and a real program cannot log the port it got. Proposed
   fix: `fn (l: Listener) addr() -> Str` in the prelude (FakeNet returns the
   in memory address), and `fn (s: Server) addr() -> Str`.
   **Resolved 2026-10-08** (decision 0055): both, as proposed; replay
   returns the recorded address.

4. **No std hashing or constant time compare for credentials.** Tokens are
   stored and compared in plain text (`WHERE token = $1`). `use go
   "crypto/sha256"` and `crypto/subtle` work through bindings (decision
   0041), but an auth service should not need Go interop for the basics.
   Proposed fix: a small `std/crypto` with `sha256(Bytes) -> Bytes`,
   `hmac_sha256(key, msg)`, `equal_constant_time(a, b) -> Bool`, and
   `Rand.token(n) -> Str` for generating tokens.
   **Resolved 2026-10-08** (decision 0056): `std/crypto` with `sha256`,
   `hmac_sha256`, `equal` (constant time), `random_bytes(r: Rand, n)`,
   `token(r: Rand, n)`, `hash_password` / `verify_password`
   (PBKDF2-HMAC-SHA256, Go standard library).

5. **`std/log` in tests writes to the real stderr, not `os.stdio`.** `xo test`
   output is interleaved with `INFO purged expired notes` lines from passing
   tests, and logs cannot be asserted. Calling `log.configure(os.stdio)` in
   each test is possible but easy to forget. Proposed fix: under `xo test`,
   the default log sink is the test's `os.stdio.errors()`, printed only when
   the test fails (like `go test`), and std/testing gains
   `fn (s: FakeStdio) logs() -> List[Str]`.
   **Resolved 2026-10-08** (decision 0057): each test has its own log
   buffer, printed only on failure or with `-v`, and
   `testing.logs() -> List[log.Record]` returns structured records.

6. **Row to struct mapping is manual.** `row_note` reads five columns by name;
   every new column touches it and the `INSERT`. Proposed fix: `fn (r: Row)
   decode[T: Json]() -> T ! SqlErr` (columns as JSON keys), or `derive Row`.
   `RETURNING` in the in memory driver would also let `insert_note` read the
   stored row instead of rebuilding it.
   **Resolved 2026-10-08** (decision 0058): `derive SqlRow`,
   `row.decode[T]()`, `db.query_as[T]` / `query_one_as[T]` (also on `Tx`),
   and `RETURNING` in the in memory driver. `row_note` is gone and
   `insert_note` is one `query_one_as[Note]("INSERT ... RETURNING *")`.

7. **`Request` lacks `with_header`, `Response` lacks `text()`.** The middleware
   copies `req.headers` into a `var`, `put`s, and uses `req with {headers}`;
   tests repeat `resp.body.to_str() ?? ""`. Proposed fix: add
   `fn (r: Request) with_header(name, value) -> Request` (symmetry with
   `Response`) and `fn (r: Response) text() -> Str?`.
   **Half resolved 2026-10-08**: `Request.with_header` added (decision
   0055); `Response.text()` is still open.
   **Resolved 2026-10-08**: `fn (r: Response) text() -> Str?` (std.md 4.3,
   collects a streamed body first); the notes-service tests use it and
   `body_of` is gone.

8. **Diagnostic: `Float.from(n)` gives XO0601 with no hint.** The conversion
   is `Float(n)` (std 2.1) but the message only says `Float` has no `from`.
   Proposed fix: when XO0601 names a numeric type's associated function and
   the argument is another numeric type, add `help: convert with Float(x)`.
   The workaround used here was `1s * n.ttl_secs`, which is cleaner anyway;
   `Duration.from_secs` takes only `Float`, so an `Int` overload
   (`Duration.from_secs_int` or a generic numeric parameter) would also help.
   **Resolved 2026-10-08** (decision 0060): XO0601 on a numeric type's
   unknown associated function with one numeric argument adds the note
   ``convert with `Float(x)` `` and a first fix rewriting `Float.from(n)` to
   `Float(n)` (applied by `xo fix`); `Duration.from_secs_int(n: Int)` added
   and used by notes-service.

## What worked well

- The `XO0701` diagnostic for a `pub fn` without `uses` named the call site
  that performed each effect; one edit fixed it.
- `match` on `Err(NoRows)` for lookups and the `from sql.SqlErr` variant kept
  error plumbing short; `?` across `SqlErr` into `ApiErr` just worked.
- `spawn_background` plus `serve` gave correct shutdown with no extra code:
  the purge loop is cancelled when `serve` returns.
- The deterministic scheduler and virtual clock made the purge job test
  exact (`os.clock.since(start) == 750s`) and instant; `run_main` plus
  `signal_after(5m)` tested a five minute run including a real purge tick.
- Over declaring `uses net.dial` for the in memory `Db` cost nothing.

## Follow up: rewrite on the new std (2026-10-08)

`examples/notes-service` was rewritten against the std additions of
decisions 0055 to 0057:

- The `/notes` routes live in their own router behind `auth`, mounted into
  the public router; `/health` needs no path comparison. `auth` returns
  `Response ! ApiErr`, so 401 and 500 bodies come from `ApiErr.status` and
  `display` like every handler error.
- `auth` hands handlers a `User` through `req.with_value(user_key(), u)`;
  the `X-Notes-User` header and its parsing are gone.
- Tokens are stored as `crypto.sha256` digests (column `token_sha256`) and
  the digest found is checked with `crypto.equal`; without `NOTES_TOKEN`,
  `main` mints one with `crypto.token(os.rand)` and prints it once.
- `run` logs `l.addr()`, so `NOTES_ADDR=127.0.0.1:0` works; the end to end
  test listens on `:0` and reads the address from `testing.logs()`.
- 13 tests (was 9): typed user, digests, `Listener.addr` on `:0`, and log
  assertions for the purge job and the whole run.

Found on the way:

- `--explore=20` plus the log assertion found a real service bug: when
  SIGTERM landed inside the purge's database call, the loop logged
  `WARN purge failed err=Canceled` (gotcha
  `canceled-error-logged-at-shutdown.md`). Fixed with `Err(Canceled) =>
  return`. The old test suite could not see it (logs went to stderr).
- Two fake network bugs (gotcha `fake-listener-before-serve.md`): a request
  to a listener before its `serve` started was refused instead of waiting
  like a socket backlog, and a background `serve` canceled before it ran
  deadlocked. Both fixed in std/rt/testing.go.

Still open from the list: 6 (row to struct mapping), the `Response.text()`
half of 7, and 8 (`Float.from` hint).
