# Fault locations as a file, line, and column, 2026-10-25

Addendum of decision 0228 (fault entry points as Xo exports: the
location was an Int, the address of a `.asciz` "file:line:col"). Every
checked operation now passes the file name's address, the line, and the
column; the runtime makes the string when the fault is recorded.

## What moved

- `compiler/ssa/ir.xo` `pos_split`: a position "file:line:col" as the
  file, line, and column (the last two colons delimit them, so a file
  name with a colon keeps its own); another shape is its whole text with
  line 0, which the runtime prints as it is.
- `compiler/arm64` (isel.xo, calls.xo, gen.xo `loc_args`): the 13 fault
  sites pass `[the operation's own arguments] + [file, line, col]`.
  `loc_label` keeps one `.asciz` per file name (it interns by the string
  it is given, now the file), so the file's text is stored once per part
  and all of its positions point at it.
- `compiler/llvm` (func.xo `loc`, call.xo): the same three arguments,
  `ptr @.loc.N` per file name (its `cstr` map keyed by the file) and two
  i64 constants.
- `std/native/llrt/cabi.xo`: the 10 checked-operation entries take
  `(file, line, col)` after the operation's own arguments;
  `fault_raise_cur` gains the position and calls `fault.set_pos`. The new
  `fault_raise_pos(m, file, line, col)` is the second raise export,
  reached through `rt.static_word` 90 (`fault.init_pos` in entry.xo).
  `fault_raise_msg(m, loc)` keeps its two arguments: `std/native/internal.xo`
  hands it to qsort as the comparator of the fault test, and the
  `fault(msg)`/contract path (`fault_raise`, bytes of a location) uses it.
- `std/native/llrt/fault.xo`: `set_pos` and `pos_text` build
  "file:line:col" into one block of `dup`'s shape at the fault (the raise
  does not return, so this costs nothing on the normal path); `fire_pos`
  raises through the new word. `raise_*` take the position;
  `fault(msg)` and contracts keep the bytes path.
- The function and part cache versions are bumped (fn v8, part v4), so no
  cached text from the previous ABI is reused. `internal/arm64`'s asm
  goldens (fib, sieve) are re-recorded by the test's `-update`.
- wasm is untouched (its own `fault_index` takes the location bytes).

## Sizes (darwin/arm64, `--release`, one source tree)

A is the checkout's cached xo of the commit before the change, B is this
change; both build the same sources with the same std.

| | __text A | __text B | __cstring A | __cstring B | binary A | binary B |
| --- | --- | --- | --- | --- | --- | --- |
| hello (`bench/size/native/xo/hello`) | 172,492 | 179,660 | 17,662 | 1,278 | 300,084 | 283,572 |
| CRUD (`bench/perf/http/xo`) | 1,412,032 | 1,444,720 | 88,910 | 5,485 | 1,999,491 | 1,949,955 |

- `__cstring` loses every location string: 562 and 2,917 strings become
  33 and 83 file names (18.0 KB to 1.3 KB, 94.2 KB to 5.5 KB).
- `__text` gains one `movz` per number and loses no relocation: +7,168 B
  (hello) and +32,688 B (CRUD), 11 to 13 bytes per converted site.
- The binary is 16,512 B (5.5%) and 49,536 B (2.5%) smaller: the saved
  strings outweigh the stub instructions.
- 18 and 175 locations are still strings: the faults generated by the
  compiler itself (`b.fault`: budgets, contracts, an unsupported runtime
  call) pass the bytes of a location through `fault_raise` and are not
  checked operations.
