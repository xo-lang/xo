# HTTP/2 download: idle workers looping on a run-next slot in its grace (2026-10-22, Xo Lang 2)

The standing gap of `net-vs-go-2026-10-22.md` (HTTP/2, 256 MiB download,
0.61 to 0.67 of Go on the quiet run) measured again on main 46a1ed503
the same day: on the Mac Xo was 1.12x Go's rate at 0.67x its CPU; in
Docker linux/arm64 Xo reached 1,082 to 1,093 MB/s against Go's 1,150
to 1,539, with 1.5 s of server CPU against 0.58 to 0.76 s. The gap is
Linux CPU.

Setup: Docker linux/arm64 (scripts/docker-linux.sh) on the Mac, the
server on CPUs 0-5, Go's net/http client (h2big, 3 downloads of 256 MiB
per run) on 6-11, server CPU from /proc; `xo bench --ab`, 10 rounds,
interleaved, Mac load 5 to 8. A is main's runtime (the same std as B
but pool.xo, poll.xo, cabi.xo), B the change; servers built with
`--backend=arm64 --targets=linux/arm64`.

## Cause

CPU profile (XO_PROF=cpu, 1000 Hz): find_work 35% cumulative,
sysio.mono_ns 13% (the vDSO clock, unnamed frames), epoll_wait 11%,
steal_round 8% flat, futex_wake 5%, all on idle workers. XO_RTSTATS over
three downloads:

| counter | main | change |
|---|---|---|
| spin_round | 4,113,167 | 64,138 |
| idle_npblock | 2,662,065 | 22,324 |
| poll_return | 598,056 | 57,428 |
| fiber_park | 7,589 | 6,327 |
| wake_push | 7,461 | 6,173 |

The connection's fiber hands work on through its worker's run-next
slot, which a thief may take only after NEXT_GRACE_NS (50 us).
`any_work` counted the slot as work, so a woken worker that could not
steal it went straight back to look again (gotchas/idle-worker-loops-on-runnext-grace.md).

Change: `any_work` returns 2 when the only work is run-next slots in
their grace; `np_block` then waits in the poller for at most the grace,
`go_idle` on its futex.

## Results

| comparison | metric | B / A | 95% interval | verdict |
|---|---|---|---|---|
| change / main | server CPU s | 0.664 (1.13 to 0.75) | 0.575 to 0.688 | better |
| change / main | MB/s median | 0.95 | 0.891 to 1.091 | within noise |
| change / main | wall ms | 1.002 | 0.966 to 1.02 | within noise |

| change / Go | server CPU s | 1.212 (0.66 to 0.80) | 1.087 to 1.381 | worse |

So Xo matches Go's rate on Linux and uses 1.21x its CPU, where it used
2 to 2.6x.

## Rejected

- One clock read per steal round instead of per victim: server CPU
  0.978 (0.908 to 1.019), within noise.
- That plus no clock read in a poll with no timer: 1.012 (0.934 to
  1.147), within noise. The clock reads were the symptom; the number of
  rounds was the cause.

## Open

- On Linux, epoll rounds the grace wait up to 1 ms, so a run-next whose
  owner keeps computing can wait up to 1 ms for a thief (50 us before).
  Next: epoll_pwait2 (syscall 441, a timespec) for waits under 1 ms,
  with epoll_wait on ENOSYS, measured with `--ab` on CRUD and Xo Lang
  3's wake-to-run latency.
- The CRUD run at 6 cores.
