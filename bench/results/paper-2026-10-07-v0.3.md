## Spec contradictions in 0.3

1. **Prefix omission for another module's enum.** Core 2.3 says the prefix may
   be omitted when the expected type is known; 3.5 shows qualified variants
   (`http.ClientErr.Canceled`) and does not say whether bare forms work for
   other modules. Hit by 2 agents (01, 03).
2. **Newline rule vs. function clauses.** A function header ending in an
   identifier or `)` followed by a newline and `uses`/`requires` is terminated
   by the 1.3 rule, yet every example writes clauses on their own lines (01).

## Persistent friction (3 runs)

1. **Value semantics in concurrent code.** Worker results need
   `Mutex[Map[Int, Result]]` plus a reorder pass in every run (02). A bucket
   update needs `Mutex.with` around `Map.update` and a result enum (05).
   Strongest consistent signal in the benchmark.
2. **Capability threading.** `os.net, os.clock, os.rand` on every call and
   matching `uses` clauses (03). A struct holding capabilities is the
   intended answer but agents did not reach for it.
3. **Cancellation arms.** Counting per file failures needs an extra
   `Err(Canceled) => return Err(...)` arm per match (04).

## Proposed changes for 0.4

1. Clauses: a newline before `uses`, `requires`, `ensures`, `invariant`,
   `derive` continues the declaration (like the leading dot rule).
2. Prefix omission works for any enum, including other modules', whenever the
   expected type is known; qualified forms are always allowed.
3. Closure and `scope` error types are inferred as the union of propagated
   errors only when all convert to one declared type; otherwise annotate
   (`XO0405` with a fix). `Never` implements every interface.
4. All compound assignments (`-= *= /= %=`); tuple access `t.0`; qualified
   types in `from`; doc comments on fields and variants.
5. Creating a closure performs no effects; calling it does. Test blocks may
   perform any effect on their fake `os`.
6. `task.map_concurrent(jobs, limit, f) -> List[Result[R, E]]` (ordered) and
   `Mutex[Map].update(k, init, f)` shortcut, to remove the two value
   semantics patterns that hurt in every run.
7. `matches!`-style test helper: `expect(x).matches(Err(Timeout))` or a
   `matches(expr, pattern)` expression.
8. `Fs.write_only()`, fuller `Set` API, and the std details above.
9. `testing.run_main(main, os)` to test `main`.
10. Treat a `Canceled` error result like the infallible case: matching `Err(e)`
    on it is allowed, but the compiler suggests `?` (vet) for clarity.
