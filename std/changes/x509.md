# std/x509 changes

## 2026-11-05: feature: parse_pkcs12 reads .pfx and .p12 files

- Kind: feature
- Commit: this commit
- Found by: the Azure SDK (a certificate credential is a PFX, decision 0006-xo-gaps in the azure repository)
- Go reference: golang.org/x/crypto/pkcs12 v0.58.0 (BSD, Copyright 2015 The Go Authors); crypto/des; the RC2 of its internal/rc2
- Test: internal/stdtest/testdata/corpus/pkcs12 (scripts/stdcorpus pkcs12.go: Go's three test files and two OpenSSL files with passwords, truncations and bit flips, against Go's result) on go, arm64 and LLVM; std/native/llrt/des_test.xo (the FIPS 46 vector) and rc2_test.xo (Go's rc2 vectors)

`x509.parse_pkcs12(data, password)` returns the private key, the leaf certificate and the other certificates of a PKCS #12 file. The native backends run a port in Xo (std/native/llrt/pkcs12.xo, des.xo, rc2.xo: the key derivation, MAC check, 3DES and RC2 decryption and bag walking of Go's package); the Go backend vendors the package (std/rt/xcrypto_pkcs12.go). Deviations: chains and several bags are read where Go's Decode wants exactly one certificate and one key, and the leaf is chosen by localKeyID. Error texts are Go's; a malformed file's asn1 wording differs.

Timing against Go's package (Mac arm64, `ToPEM` against `parse_pkcs12` on a 3 KB chain file with 2048 iteration keys, 20 parses, release build; 2026-11-05): Go 15 to 21 ms, Xo 31 ms, so 1.5 to 2.1 times slower. The profile: RSA key import (bigmod, shared with `crypto.parse_private_key`) 21%, SHA-1 compression 12%, the key derivation's per iteration `sha1.sum` allocations about 25%, 3DES 12%. The 3DES feistel box is built from 128 permutations, not Go's 512. Next: a hashing loop without a Bytes per iteration.


## 2026-10-29: fix: a bracketed IP named in a hostname error

- Kind: fix
- Commit: this commit
- Found by: the verify_hostname corpus rows (std API coverage, TestStdAPICovered)
- Go reference: crypto/x509 (Certificate.VerifyHostname, HostnameError.Error) (go1.26.1)
- Test: internal/stdtest/testdata/corpus/x509 (scripts/stdcorpus x509.go HOST_ROWS: 406 hosts against each certificate's names, case, a trailing dot, wildcard labels, IPs bracketed and not, against Go's VerifyHostname) on go, arm64 and LLVM

`verify_hostname("[::1]")` on a certificate without IP SANs said "not
valid for any names, but wanted to match [::1]" natively; it now says
Go's "cannot validate certificate for ::1 because it doesn't contain any
IP SANs" (std/native/llrt/tlsname.xo hostname_msg strips the brackets
when the inside parses as an IP). A TLS handshake to a bracketed IP host
reports the same corrected text.

## 2026-10-29: feature: creating certificates and requests, parsing CRLs

- Kind: feature
- Commit: this commit
- Found by: the owner's queue after milestone 0.35.0 S5 (certificate creation, CSRs, CRL parsing)
- Go reference: crypto/x509 (CreateCertificate, CreateCertificateRequest, ParseCertificateRequest, CertificateRequest.CheckSignature, ParseRevocationList, RevocationList.CheckSignatureFrom, MarshalPKCS8PrivateKey), generate_cert.go (go1.26.1)
- Test: internal/stdtest/testdata/corpus/x509create (scripts/stdcorpus x509create.go: every template made by Go and by Xo with Go's test keys, equal bytes for Ed25519 and RSA and equal fields for ECDSA; Go's requests and CRLs and mutated copies against Go's fields and errors; self_signed; marshal_private_key against Go's PKCS #8) on go, arm64 and LLVM

New in std/x509 (spec std.md 41): `create_certificate(r, t, public_key,
parent, key)` with a `Template`, the development helper `self_signed(r,
hosts, now, days = 30)` returning certificate and key PEMs,
`Certificate.pem()`; `create_request`, `parse_request`,
`CertificateRequest.check_signature` and `pem`; `parse_revocation_list`
and `RevocationList.check_signature_from`. The DER writers are in
std/native/llrt/asn1.xo.

Timing against Go's crypto/x509 (bench/perf/x509, quiet `xo bench --ab`,
15 rounds, Go as A): create wall 2.676 (2.664 to 2.685), instructions
2.586, slower, and 99% of the profile is Ed25519 signing and verifying
(std/native/llrt/ed25519.xo), which the queued Edwards25519 port (Go's
51-bit field) addresses; parse wall 0.842 (0.834 to 0.85), instructions
0.879, faster; parse_revocation_list (crl) wall 0.394 (0.389 to 0.404),
instructions 0.361, faster.

## 2026-10-29: feature: std/x509, certificate parsing and chain verification

- Kind: feature
- Commit: this commit
- Found by: milestone 0.35.0 S5 (public x509 from the parser and verifier TLS already has)
- Go reference: crypto/x509 (ParseCertificate, Certificate.Verify, VerifyHostname, CheckSignatureFrom, SystemCertPool's sources), crypto/x509/pkix (Name, Name.String) (go1.26.1)
- Test: internal/stdtest/testdata/corpus/x509 (scripts/stdcorpus x509.go: every certificate of Go's crypto/x509 and crypto/tls testdata, a fifth of the NIST PKITS certificates, verify_test.go's certificates and truncated and bit-flipped copies, each field and error text against Go's ParseCertificate; verify_test.go's verifyTests rows with roots against Go's Verify chains and errors; Name escapes) on go, arm64 and LLVM; bench/perf/x509 twin

New module std/x509 (spec std.md 41): `parse(der)` and `parse_pem(pem)`
give a `Certificate` (raw DER, version, serial, Go's signature algorithm
name, issuer and subject `Name`s with Go's `display()` and every
`attributes()`, validity, `crypto.PublicKey`, DNS names, IP addresses,
e-mail addresses, URIs, basic constraints, key usages, extended key
usages, key ids and every extension). `Certificate.verify(opts)` is Go's
Verify with explicit roots, intermediates, DNS name, time and key
usages, returning every chain or Go's error text; `verify_hostname`,
`check_signature_from`, and `system_roots(fs)`, the roots std/tls
checks servers against (on macOS the system's anchor certificates). The
native backends wrap the TLS stack's parser and verifier
(std/native/llrt/x509cert.xo, x509verify.xo), which now also keep every
extension, the Go backend Go's crypto/x509.

bench/perf/x509 against Go's crypto/x509 (quiet `xo bench --ab`, 15
rounds, Go as A, wall): parse_pem of a three certificate chain 1.183,
verify 1.002. The PEM scan (std/native/llrt/tlsname.xo find_at, shared
with std/tls and std/http's PEM roots and keys) compares a marker's first
byte before the rest: parse_pem 0.865 of the parent's wall.
