# std/tabwriter changes

## 2026-11-10: refactor: one file with its bodies (decision 0588 stage 2)

- Kind: refactor
- Commit: this commit
- Found by: decision 0588 stage 2 (pure modules merged with their implementation)
- Go reference: none (no behavior change)
- Test: internal/stdtest corpus tabwriter on go, arm64 and llvm

std/tabwriter.xo now holds the bodies of std/native/tabwriter.xo (removed), and the Go
backend compiles them from it as its own package, in place of the hand written std/rt/tabwriter.go (removed): the
Go backend now runs the same tabwriter code as the native backends. The API, texts and errors
are unchanged: every item the declaration file had is `pub`, with the same
parameter names.

## 2026-11-08: perf: update_width counts ASCII bytes inline

- Kind: perf
- Commit: this push
- Found by: xo prof of bench/perf/tabwriter (rune_len 19% flat, update_width 26% cumulative)
- Go reference: text/tabwriter's updateWidth (utf8.RuneCount over the new text; Go counts ASCII bytes without a decode call)
- Test: internal/stdtest corpus tabwriter (arm64, LLVM, Go backend); bench/perf/tabwriter output unchanged
- Timing: bench/perf/tabwriter on linux/arm64 host 1, --ab against the parent (6 rounds, stopped early): pad 0.957 (0.951 to 0.962), right 0.949 (0.945 to 0.954), none within noise (1.001)
- Shipped in: not yet released

`update_width` (std/native/tabwriter.xo) called `rune_len` for every byte; it now tests for an ASCII byte in the loop and calls `rune_len` only for a multi byte one, and keeps the width in a local. Output is unchanged.

## 2026-10-29: port: std/tabwriter, Go's text/tabwriter

- Kind: port
- Commit: this commit
- Found by: the std-vs-Go survey (item 12: CLI tables were padded by hand)
- Go reference: text/tabwriter/tabwriter.go (Writer, Init, Write, Flush: format, writeLines, writePadding, the Escape and HTML filters) and tabwriter_test.go (go1.26.3)
- Test: internal/stdtest/testdata/corpus/tabwriter, generated by scripts/stdcorpus/tabwriter.go from Go's own test table, each case written all at once, byte by byte and in Fibonacci slices, on the native backends (arm64 and LLVM) and the Go backend
- Timing (2026-10-29, quiet --ab, 10 rounds, 20 tables of 5000 rows): Xo 36.0 ms against Go's text/tabwriter 29.1 ms, so 1.24x slower (instructions 1.05x); wall B/A 0.809 (0.793 to 0.821)

`tabwriter.writer(min_width, tab_width, padding, pad_char, flags)` makes a move only `TabWriter`; `write(bytes)` collects text and `flush()` returns it with the columns aligned. The native backends run an Xo port of Go's code (the Go backend runs Go's own Writer over a buffer): the output Go writes to its io.Writer as lines complete is held until `flush`.
