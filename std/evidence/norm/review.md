Security review of std/norm (std/norm.xo, which the Go backend also
compiles; its tables generated by scripts/gennorm from
golang.org/x/text/unicode/norm v0.43.0) against
knowledgebase/infrastructure/std-security-checklist.md (decision 0616),
by Xo Lang 3. std/norm is Unicode normalization (NFC, NFD, NFKC, NFKD)
and is_normalized (spec/std.md). It reads text a peer sends: user names
and identifiers a program compares, and every name std/idna maps.

## 1. Go's CVE history

The Go vulnerability database (vuln.go.dev, searched 2026-11-14 for
golang.org/x/text; 182 stdlib entries read for siblings) has one entry
for x/text/unicode/norm:

- GO-2026-5970 (norm.Iter looped forever on some invalid UTF-8). Not
  applicable: std/norm has no iterator, only normalize and
  is_normalized over a whole Str, and a Str is valid UTF-8 by
  construction (spec core), so invalid input cannot reach it. The main
  loop advances by the width of each lead byte (norm.xo:54-81), never by
  zero.
- GO-2020-0015 (x/text/encoding/unicode), GO-2021-0113 and GO-2022-1059
  (x/text/language): other packages of x/text; std/norm does not port
  them.

Sibling classes, checked:

- Quadratic reordering of combining marks (the class UAX #15 section 13
  "stream-safe text" exists for; x/text bounds it with
  maxNonStarters = 30): F1.
- Output growth: a rune's decomposition is a fixed table entry (the
  longest, U+FDFA in NFKD, 18 runes), and F1's fix adds one U+034F per
  30 non-starters, so the output is at most a constant times the input.

## 4. Fault behaviour

### F1 (fixed in 3a99cbf9e, to ship in 0.51.2): reordering was quadratic and diverged from x/text past 30 non-starters

normalize sorted each run of combining marks by combining class with an
insertion sort over the whole run, so a text of n marks after one
starter cost n squared steps: 32,000 marks 88 ms on the Mac, and the
cost grew with the square of whatever a peer could send in one field.
x/text applies UAX #15's stream-safe rule instead: past 30 non-starters
in a row it inserts U+034F and normalizes each side alone, so its output
differed from Xo's on such text (3,464 of 16,000 fuzz checks on the
first seed). 0.38.0 to 0.51.0, every backend. Found by the new fuzz
harness on its first seed.

Fix: each rune counts its decomposition's leading and trailing
non-starters (x/text's nLeadingNonStarters and nTrailingNonStarters,
which scripts/gennorm probes through x/text's public API into the
STREAM_SAFE and SS_IDX tables, one set for every form, checked against
NFKD); a starter sets the count to its trailing ones; past 30 a U+034F
goes in and the text on each side is normalized alone. gennorm makes
every rune with a leading count unstable, so only a run of unstable
runes can pass 30, and only a run longer than 20 bytes is counted
(flush_run). After: 32,000 marks 1 ms; output equal to x/text's. Cost
on ordinary text 2 to 3% (bench/perf/norm, host 1 --ab), recovered by
a per block index of the unstable tables (NFC_UIDX, NFKC_UIDX; nfc
0.853, nfkc 0.904 against main, 783353491). Tests: std/norm_test.xo; TestNormFuzz seed 1 on
arm64, llvm and go, seed 2 on arm64 and llvm; TestStdCorpora norm and
idna; stdgen -check; std/changes/norm.md and the CHANGELOG security
line.

### F2 (fixed in 787450d2e, before F1 shipped): F1's counts missed runes of class 0 that combine backward

x/text counts a rune of class 0 that combines backward (U+0B57, U+0CC2,
U+11930: NFC's quick check says Maybe) as one leading non-starter, so a
run beginning with one reaches 30 a mark sooner. scripts/gennorm
measured the stream-safe counts of only the runes a form changes or of a
class above 0, so those runes had none in STREAM_SAFE, and std/norm put
the U+034F one mark later than x/text: different text, not a cost (the
bound of F1 holds either way). Found by TestNormFuzz seed 59 on host 2
(4 of 40,000 checks; 58 seeds had passed). Fix: gennorm also measures
every rune with no boundary before it in NFC or NFKC; STREAM_SAFE and
SS_IDX regenerate, the other tables unchanged. Tests: std/norm_test.xo
"a rune of class 0 that combines backward counts as a non-starter"
(11 leads with x/text's offsets); TestNormFuzz seeds 59 to 61; the
fuzz, stress and race evidence rerun at this source.

### Fault sites

- None. norm.xo has no or_fault, unwrap or fault call. normalize and
  rune_at (214-225) read up to 3 bytes after a lead byte of that width
  in a Str, which is valid UTF-8. Table reads (rd2, rd3, find_rec,
  push_decomp) use offsets from generated index tables; `Rune(x)` in
  flush_run converts code points that come from the input or the
  generated decompositions, all valid scalar values (gennorm takes them
  from x/text).

## 5. Defaults

- No options. The forms are Unicode's; the stream-safe limit is
  x/text's 30 and cannot be raised.
