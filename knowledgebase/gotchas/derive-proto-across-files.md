# derive Proto across files: private types, enums and other packages

Status: Observed 2026-11-16 (task #102, xo proto gen with imports)

## Symptom

Code generated by `xo proto gen` for two .proto files, one importing the other, failed to build in
one directory: `XO0601: function proto_unmarshal__A not found (in the code derive generates for this
field)` for a field of type `A` from the other file, the same for an Int enum from the other file
(`proto_zero__K`), `XO0425` for a field of type `protowkt.Timestamp`, and `XO0110: import std/protobuf
is never used` in every generated file, a single one included.

## Cause

- The functions `derive Proto` writes for a non-`pub` struct are not visible from another file of the
  same package, though the struct itself is.
- `derive Proto` maps an Int enum of the same file only, and a struct of the same package only
  (std/protowkt's types are another package).
- The generated code calls into std/protobuf without the `use` counting as used.

## Fix

std/protoparse writes `pub` types and fields and no `use` line (cmd/xo TestProtoGenBuilds builds the
output), and `gen_set` refuses an enum of another file or a type outside the set with a clear error.
An enum of another file and the well-known types need derive Proto changes in compiler/check/derive.xo.
