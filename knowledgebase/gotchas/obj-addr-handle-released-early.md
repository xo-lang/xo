# a handle released before the runtime call that uses its address (Observed 2026-10-29)

Symptom: Linux TSan (--race, arm64) `heap-use-after-free` in chan.recv_w (pool.lock_k, chan.xo:694),
TestRaceSyncTable chan. Darwin silent (race heap is not libc malloc/free, memory stays mapped).
Cause: Chan[Int] ops pass `rt.obj_addr(h)` (conc.xo chan_word) to llrt_chan_*_w; rc.xo saw h's last
use at obj_addr, so the release came BEFORE the call; the sender's task end then freed the channel.
Fix: per site: conc.xo chan_hold calls the prelude's llrt_chan_hold[T] after each word channel op, using the handle. The general rule (rc.xo: an rt.obj_addr result borrows its handle) failed the inliner's verify, because std code moves a handle after taking its address on purpose. Select's word arms had none until 2026-11-02 (Xo Lang 2): a send arm's channel was released before select_send_w took its reference (rc.inc on freed memory) and a word receive arm's select before select_take_w (select_arm_order under --race on Linux); conc.xo now uses each after its call: chan_hold_t (llrt_chan_hold[T] with the channel's element as a checker type; a first try passed the SSA type id from b.vty to b.declare, which takes checker ids, and instantiated an unrelated type) and a second b.chan_word(sel) after select_take_w (the Select handle is the SSA's own and has no checker type for a generic hold). The same code chose a receive arm's word path from b.word_chan of a checker type id (word_chan reads SSA types), so whether a receive arm took select_take_w depended on an unrelated type; it now reads the SSA element type as the send arm does.
Check: test/codegen/chanrc; Docker: scripts/docker-linux.sh arm64 (race_sync, XO_THREADS=1, XO_RACE_CASE=chan).
Lesson: darwin hides use-after-free of Xo heap blocks; a Linux TSan run is the detector.
