# Agent rules registry

Every rule agents follow, its one home, what enforces it and the test that
proves the enforcement (task #139, owner 2026-11-16). A rule whose
enforcement is `none` lives only in prose (CLAUDE.md or a memory) and is
the first candidate for a tool check when it is broken again.

Read by machines, so keep the shape:

- `internal/repotest` `TestAgentRulesRegistry` (in `go test -short`, so the
  hourly main check runs it) fails when a listed enforcement or test path
  is missing. Paths are repo-relative, `~/...` (checked when it exists on
  this machine's lead directory), or `workstream:PATH` (the private xw
  repository, checked when `~/godev/claude-space/xolang/workstream`
  exists). The `~/` and `workstream:` paths are read from the live machine,
  so they fail the test only when this tree's registry is current (the
  tree holds origin/main, or its agent-rules.md is main's); on a release
  branch cut before a rename they are logged (task #659, 2026-11-21).
  A `(name)` after a path names the function or check inside it.
- xw reads the Incident kinds column: an alert kind (main failures are the
  `main-check`, `tier`, `tier-new`, `bisect` and `sched-failed` kinds) raised 3 times in 7 days that no
  row with an enforcement lists raises a `rule-gap` alert to the lead.
- xw reads the Schedules table: a schedule whose evidence is older than
  twice its period raises `schedule-missed` to the lead, unless the row's
  Waits on beat is due in the future: the loop that runs it is on a
  documented skip (mainwatch: no run 00:45 to 03:30, the quiet window, up
  to MAINWATCH_LOAD_WAIT for load; task #210). A beat past due is
  `loop-stale` and the late schedule alerts again.

## Schedules

A periodic job that is not a launchd agent is a line of xw's schedule,
`~/xo-lead/xw-schedule.conf` (`NAME EVERY [VAR=VAL...] COMMAND [ARGS...]`, EVERY like 8h or 30m,
COMMAND relative to `~/xo-lead` while ARGS are passed as written, and
VAR=VAL words run it under /usr/bin/env with them since workstream
fc6b4b9; xw sched.xo, 2026-11-18):
the alert pass starts it when due, its output is `xw/sched/NAME.out`
(the row's evidence), and a run that exits nonzero is a sched-failed
alert carrying its last `SCHED-TRAP: ` line.

A schedule or loop stopped on purpose is paused in xw, not left to
alert: `XW_AS=lead xw schedule pause NAME --until TEXT` (NAME a row
below, a loop beat, or an xw schedule job), `xw schedule resume NAME`,
`xw schedule list` (#325, 2026-11-19). A paused NAME raises no
schedule-missed (its row, or a row whose Waits on is `beat:NAME`), no
loop-stale, and its alerts are left out of rule-gap's count; a paused
xw schedule job does not start. Mainwatch and ctier, paused by the owner
