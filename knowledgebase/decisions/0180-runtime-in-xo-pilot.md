# 0180: The native runtime in Xo, pilot: the Unicode operations

Status: Accepted (2026-10-12, runtime pilot of decision 0150's amended
order), implemented: `std/native/llrt/unicode.xo`,
`std/native/llrt/unicode_tables.xo` and `std/llrt/xo_unicode.c` (both
generated by `internal/llvm/unicode_test.go`),
`std/native/llrt/unicode_c.xo` (the C path), `internal/check/load.go`
(`loadRuntimeModule`) and its mirror `selfhost/check/load.xo`
(`load_runtime_module`), `internal/ssa/build_expr.go` and
`selfhost/ssa/expr.xo` (`a.to_lower() == b.to_lower()`),
`std/native/rt.xo` (`rs_append_bytes`, `bytes_span`, `rs_push_byte`,
`rs_push_rune`, `rs_with_cap`), `std/llrt/xo_bytes.c` and `xo_std.c`
(the new primitives; the old C under `#ifdef XO_UNICODE_C`),
`internal/build/tzdata.go` (`IOFlags`). Tests: golden `unicode_table`
(Go, LLVM, arm64), `TestUnicodeTables`, `TestNativeModules`,
`TestUnicodeCPath`, `TestIOFlagsUnicodeC`. Evidence:
`bench/results/runtime-pilot-2026-10-12.md` (`bench/perf/unicode`).

## Context

The native backends (arm64, LLVM, `--no-gc`) link the C runtime std/llrt
(14 files, 26,240 lines on 2026-10-12). Decision 0150 (amended order,
item 6) asks for a pilot: write one piece of it in Xo, `xo_unicode.c`
(1,783 lines), and decide on that evidence whether to port more.

`xo_unicode.c` was data only: Go's case ranges and the letter, digit, and
`strconv.IsPrint` ranges as C arrays, generated by `TestUnicodeTables`.
Its users were C: `n_to_case` (Str and Rune `to_lower`/`to_upper`, the
`a.to_lower() == b.to_lower()` comparison `xo_str_eq_lower`), the Rune
classes, strconv quoting (`Str.quote`, `Rune.quote`, `Bytes.quote`, the
duration parse error), and `xo_unicode_ranges` (std/regexp's `\pL`,
`\p{Nd}`, decision 0172). Porting the tables alone would leave C reading
Xo data, so the pilot ports the tables and every user of them.

Constraints: output identical to the Go backend; the self hosted
compiler mirrors the checker and SSA builder (Xo source under std/native
is shared, compiler changes are made twice); the runtime pack (decision
0157) is keyed by the C sources; another agent writes a wasm backend
(selfhost/wasm), which cannot link C.

## Decision

1. **Runtime modules.** A runtime module is `std/native/llrt/<name>.xo`,
   module path `native/llrt/<name>`. It is loaded when an implementation
   module (std/native/<name>.xo, the native prelude) or another runtime
   module imports it, never for user code (module not found, as for
   `native/rt`), and only for native builds. It is checked like an
   implementation module (`Native`, no std module implemented) and
   compiled **with the program** by the ordinary SSA builder and
   backends: nothing precompiled into the runtime pack, no new symbol
   convention, no C ABI export. Only reachable functions are emitted.
2. **Tables are Bytes constants.** Each table is a `pub const X: Bytes =
   b"..."` of 24 bit big endian values, emitted as static data (a Bytes
   literal is an `OpConst`) and read with `b[i]` (an inline load). A
   `const List[Int]` would be built at first use and read through
   `const_once`, a C call per access. `TestUnicodeTables` writes
   `unicode_tables.xo` from the same Go tables (Unicode 15.0.0), plus
   direct tables for U+0080 to U+07FF (case mappings, class bitmaps), so
   Latin, Greek, Cyrillic, and the other two byte scripts need no search.
3. **C callers.** None remain: every C user of the tables moved to Xo
   with them (case mapping, classes, quoting, regexp ranges, the lower
   compare). The SSA builder's lowering of `a.to_lower() ==
   b.to_lower()` calls the native prelude's `str_eq_lower` instead of
   `xo_str_eq_lower` (mirrored in selfhost/ssa). Rule for later ports: a
   C function that needs a ported function is ported with it, or the
   port waits (superseded by decision 0204, 2026-10-13: C may call
   runtime functions compiled from Xo); C never calls compiled Xo (that would need an export
   symbol convention in both backends and both compilers, and every
   program would have to emit the callee).
4. **What stays C: bulk byte moves and scans.** Xo has no inline byte
   store into a string under construction (`BytesBuilder.write_byte` is
   a C call per byte), and narrowing conversions (`UInt8(x)`, `Rune(x)`)
   are checked C calls. The text operations build their result in a Str
   through `rs_*` intrinsics (appended in place when unique) and hand
   whole stretches to two primitives: `rt.bytes_span(b, i, class)` (the
   end of a run of ASCII, or of bytes strconv.Quote keeps) and
   `rt.rs_append_bytes(s, b, lo, hi, mode)` (copy, mapping ASCII letters
   for mode 1 lower or 2 upper). All Unicode policy (tables, decoding,
   which runes change, escapes) is Xo. `Rune(UInt8)` is free, so ASCII
   results of `Rune.to_lower` go through a 256 byte table.
5. **Performance bar:** no measurable slowdown on Str heavy work,
   `bench/perf/unicode` (to_lower and to_upper of ASCII and of mixed
   script text, the lower compare, the Rune classes, Rune case mapping,
   quoting) on both native backends, instructions retired and best
   times. **Result (2026-10-12): met on ASCII text and quoting, met on
   LLVM within 17 percent, not met on arm64 for per rune work.** Against
   the C path (instructions retired): `to_lower`/`to_upper` of ASCII
   0.63x to 0.67x on both backends, `quote` 0.77x to 0.79x; on LLVM
   mixed script case mapping 1.02x, the lower compare 1.13x, Rune case
   mapping 1.17x, classes 0.87x; on arm64 mixed script case mapping
   1.45x, the lower compare 1.62x, classes 1.46x, Rune case mapping
   1.80x. Cause: the arm64 backend inlines only leaf functions, in one
   round, so the prelude wrapper (`Rune.is_letter` calling
   `unicode.is_letter`) and decode, to_case, and the searches stay
   calls (before, the wrapper's only call was C, so it was inlined); its
   byte loops cost about 14 instructions a byte (a bounds check and the
   data address recomputed in the loop, Bools materialized and tested
   again). Running the inliner to a fixed point (an experiment, not
   committed) gains 0 to 11 percent only. The first, all Xo version
   (results built byte by byte) was 2 to 11 times slower than C.
6. **The C path stays selectable** because of the arm64 result:
   `XO_UNICODE=c` (read by the Go checker) loads
   `std/native/llrt/unicode_c.xo`, the same API over the C functions,
   which stay in std/llrt under `#ifdef XO_UNICODE_C` (`xo_unicode.c`,
   generated with the Xo tables). A build whose code calls them adds
   `-DXO_UNICODE_C` (`IOFlags`, as for XO_FS), so it compiles the
   runtime locally: packs never contain the C path and keep their 32
   variants. The Xo path is the default. The self hosted compiler has no
   switch (always Xo).
7. **No go for porting more of llrt (xo_rt.c next) until** (a) the
   arm64 backend inlines small non leaf functions and forwarders, keeps
   loop invariant addresses out of loops, and drops bounds checks a loop
   condition proves, and (b) `bench/perf/unicode` is within 5 percent of
   `XO_UNICODE=c` in instructions on every workload on both backends.
   **Status (2026-10-12): (a) and (b) met on arm64 (decision 0184), (b)
   met on LLVM (decision 0192: every workload below the C path, the
   lower compare 0.948x, Rune case mapping 0.967x); 7(b) holds on both
   backends** (bench/results/runtime-pilot-2026-10-12.md, section "LLVM
   value ranges and inlining").
   When (b) holds, unicode_c.xo, the `XO_UNICODE_C` C, and xo_unicode.c
   are deleted (a new ADR: decision 0198 deleted them, 2026-10-13, and
   with them `XO_UNICODE`). xo_rt.c itself (6,451 lines: reference
   counts, lists, maps, strings, fibers, the scheduler, faults and
   unwinding) is mostly below what Xo can express (raw memory, atomics,
   stack switching); after (b) the order is the policy code over Xo
   values first (xo_std.c's number and duration text, xo_json.c's
   parser), each with the same before/after benchmark and a C path
   kept until it is met, and of xo_rt.c only the parts that need no raw
   memory primitive.
8. **wasm.** A runtime module is Xo compiled with the program, so a
   wasm backend (selfhost/wasm) gets the Unicode operations as wasm with
   no C, provided it implements the five intrinsics they use
   (`rs_append_bytes`, `bytes_span`, `rs_push_byte`, `rs_push_rune`,
   `rs_with_cap`) besides the Str basics; it has no C path to fall back
   to. Every later port shrinks the runtime a wasm backend must supply,
   which is the strongest reason to meet the criteria of 7.

## Consequences

- The native runtime's Unicode tables and policy are Xo, checked and
  compiled like std/native; the self hosted compiler compiles the same
  file, so a change is made once. The compiler changes were the loader
  (Go and selfhost/check) and the lower compare's call (Go and
  selfhost/ssa; TestSelfhostSSA on the arm64 backend over unicode_table,
  strings, and regexp_table: 293 functions identical).
- Output is unchanged: the golden `unicode_table` (every scalar value
  classified and case mapped, per plane sums, string case mapping with
  Go's special cases, quoting, `\pL`) is identical on Go, LLVM, and
  arm64 with either path, and the 19 goldens that use Str case mapping,
  classes, or quoting pass on LLVM and arm64.
- Sizes: the default runtime object shrinks (rt.o 450,112 to 424,864
  bytes); the pack key changes (as for any std/llrt edit; builds stay
  reproducible). The darwin/arm64 pack's runtime objects shrink from
  16,546,544 to 15,769,664 bytes (4.7 percent; 17,776 to 17,136 KiB with
  the TLS library). A program binary grows about 16.5 KB: the
  Bytes tables (25.0 KB of data with the direct tables) replace 16.7 KB
  of C arrays.
- ASCII case mapping is faster than before on both backends (one C scan
  and one C copy per ASCII stretch, decided by Xo); per rune work is
  slower on arm64 until the criteria of 7 are met.
- Gotcha recorded: `gotchas/xo-runtime-byte-loops.md`.

## Alternatives

- **Precompile the Xo runtime into the pack.** Would need a C ABI export
  convention and stable symbols in both backends and both compilers, and
  objects per backend; rejected: compiling with the program costs only
  the reachable functions and keeps one pipeline.
- **C keeps the string loops and calls Xo per non ASCII rune.** Keeps
  ASCII speed without the bulk primitives, but needs the export
  convention above and forces the callees into every program.
- **Tables as `const List[Int]`.** One `const_once` C call and a list
  index per probe; rejected for Bytes constants.
- **Delete the C now.** Rejected because of the arm64 result (decision
  6); the C path costs nothing in packs or default builds.
- **Fix the arm64 inliner in this change.** A backend change mirrored in
  selfhost/arm64 with every arm64 golden's assembly at stake, and the
  fixed point experiment shows it is not enough alone. Left to the
  native backend work, with the criteria of 7.
