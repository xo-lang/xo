# 0358: Plain error messages for std's error enums

Status: Accepted (owner, 2026-10-23, on Xo Lang 3's proposal relayed by the
lead; Xo Lang 3). Rolled out by module; each push records its std change.

## Context

Std's error enums `derive Display`, and derived `Display` prints the Debug
form (core 2.9: `NotFound(id: 42)`). That suits a user's own enum and not
a message a person reads. Two layers stack: the enum's own text is variant
syntax (`Io(msg: "x")`), and code that wraps one error in another writes
`Conn(msg: "${e}")`, which embeds that syntax in a string. The Intel field
report on 0.26.0 printed `Conn(msg: "Io(msg: \"tls: ...\")")`, with
escaped quotes, for a failed TLS handshake under the Postgres driver, and
`Conn("Denied(addr: ...)")` where the spec said `denied by Net.only`.
14 std error enums derive Display (FsErr, NetErr, IoErr, ProcErr, EnvErr,
ClockErr, SqlErr, ClientErr, HttpErr, WsErr, CliErr, DecodeErr, ZoneErr,
CivilErr); 20 goldens print the variant syntax.

## Decision

1. Each std error enum has a hand written `display`: one plain sentence,
   no variant name, no quotes around a message. Examples: `NetErr.Io(msg)`
   prints `msg`; `Refused` `connection refused`; `Timeout` `i/o timeout`;
   `Denied(addr)` `denied by Net.only: ADDR`; `FsErr.NotFound(path)`
   `PATH: no such file or directory`; `SqlErr.Conn(msg)` `connection: MSG`;
   `Syntax(msg)` `syntax error: MSG`; `NoRows` `no rows in result set`;
   `Mismatch(column, msg)` `column COL: MSG`. Each module's section in
   spec/std.md lists its texts.
2. The Debug form stays (`${e:?}`, `e.debug()`), so a program that wants the
   variant prints it. A test that compares values (`expect(e) == Err(...)`)
   is unchanged; only programs and goldens that match the text change.
3. Code that wraps an error uses the inner error's plain display, so a
   nested text is one level (`connection: tls: handshake failure`), with no
   escapes.
4. User types are unchanged: `derive Display` keeps printing the Debug
   form (core 2.9), and core 2.9 gains one sentence saying std's error
   enums print plain messages.
5. The Go backend prints the same texts (its error values come from the
   same enums, so the display is shared).
6. Rollout, one push per group, each with its `std/changes/MODULE.md`
   entry (kind: behavior), the goldens regenerated by inspection and Go
   parity: net, io, fs, env, proc, clock (std/prelude.xo); then sql; http
   (client and server); ws; cli; the decode, zone and civil errors with
   their modules.

## Consequences

- Error messages read as sentences everywhere a program prints an error.
- A program matching error text (a `contains("Io(msg")`) breaks; the std
  change entries say so, and the repository's own occurrences are fixed in
  the same pushes.
- Two more lines of source per variant in std (a `display` per enum).

## Alternatives

- Fix only the wrapping sites (use a message field, not `${e}`): removes
  the nesting, leaves `Conn(msg: "...")` at the top level.
- A `message()` method beside `display`: keeps Display as is, so a plain
  `println(e)` stays ugly unless every caller changes.
