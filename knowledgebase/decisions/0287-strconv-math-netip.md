# 0287: Number bases, Go's math bit for bit, and std/netip

Status: Accepted (owner, 2026-10-20)

## Context

The 2026-10-20 survey of five backend services ranked small gaps
twelfth: hex text of an Int (request ids, colors, checksums), float math
(pricing, geo distance, exponential backoff), and IP and CIDR checks
(trusted proxies, allow lists). The coverage table listed strconv, math,
math/bits, and net/netip as partial or missing. Decision 0276: std
follows Go's scope, code, and tests with Xo's own API.

## Decision

1. strconv in the prelude: `Int.parse_base(s, base)`,
   `n.to_str_base(base)`, `Bool.parse(s)`, `s.unquote()`, Go's ParseInt,
   FormatInt, ParseBool, Unquote; every Go error is None; a base outside
   0 and 2 to 36 faults.
2. math and math/bits in the prelude: Float `pow`, `exp`, `exp2`,
   `expm1`, `log`, `log2`, `log10`, `log1p`, `sin`, `cos`, `tan`, `asin`,
   `acos`, `atan`, `atan2`, `sinh`, `cosh`, `tanh`, `cbrt`, `hypot`,
   `mod`, `is_inf`, `to_bits`, `Float.from_bits`; Int `leading_zeros`,
   `trailing_zeros`, `ones_count`.
3. std/netip, a module as Go's package: `Addr` (a value: its bit length,
   16 bytes, zone; ordered as Go's Compare), `Prefix`, `parse_addr`,
   `parse_prefix`, `addr_from_bytes`, the Is predicates, `contains`,
   `masked`.

**Identical floats on every backend and architecture** (owner and lead,
2026-10-20). Go itself is not bit identical across architectures: on
arm64 its compiler fuses `x*y+z` into FMA in the pure Go math, and on
amd64 Exp, Log, and Hypot run different assembly algorithms. So "Go's
results" means Go's portable algorithms (exp.go, log.go, sin.go, ...)
with every operation rounded, which is Go on amd64 at GOAMD64=v1 for the
functions without assembly. The native backends run a line by line port
(std/native/llrt/gomath.xo); the Go backend runs a copy of Go's source
with every float64 product wrapped in `float64(...)`, which the Go spec
says forbids fusion (std/rt/gomath_gen.go, generated by scripts/gomath),
not package math. Sqrt, Floor, Ceil, Trunc are exact anyway and keep
their instructions. Every Float operation in Xo rounds on every backend;
golden float_no_fma fails if a backend starts fusing (an arm64 fmadd
peephole, LLVM's contract flag, Go's compiler).

## Consequences

- Building this found the Go backend letting Go fuse Float `a*b + c` on
  arm64 in ordinary programs (gotchas/go-backend-fused-float.md); it now
  prints products as `float64(a * b)`.
- Xo orders NaN after +Inf where Go compares IEEE, so ported numeric
  code checks `is_nan` before ordering comparisons
  (gotchas/nan-ordering-in-ports.md).
- The prelude methods are std code, not compiler intrinsics, and the
  compiler does not use them, so no seed cut is needed
  (gotchas/seed-older-than-intrinsics.md).
- Deferred: Float constants (`Float.PI`, `Float.INF`, `Float.E`). An
  associated constant needs compiler lowering (as `Time.UNIX_EPOCH`
  has), which makes it seed aware; it is its own change.
  `Float.parse("inf")` gives infinity meanwhile.

## Tests

Go's results generated from Go's own code: strconv on 2,813 random and
quote_test.go cases (std/native/prelude_test.xo); math on 21,465 special
(±0, ±Inf, NaN, subnormals, the reduction threshold) and random cases,
the reference being Go's math package without its assembly compiled for
linux/amd64 v1 and run in Docker (std/native/llrt/gomath_test.xo);
net/netip on 3,323 address and prefix cases (std/native/netip_test.xo);
each also run through the Go backend with the same results; golden
float_no_fma on arm64, LLVM O1 to O3, Go, and wasm.

## Alternatives

- std/strconv and std/math modules (decision 0279's module per Go
  package): the number methods already live on the prelude's types
  (`Int.parse`, `Float.sqrt`), so the new ones join them; std/netip is a
  module, as Go's package is.
- The C library's libm natively: faster for some functions, but its
  results differ between platforms in the last bit, and the Go backend
  would not match.
- Package math on the Go backend: it fuses on arm64 and runs assembly on
  amd64, so the backends would differ.
